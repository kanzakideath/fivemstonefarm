# AI採掘機 v6.2.0

FiveM上の対象ボタンを構造的に検出し、採掘・石洗い・砂金採りを繰り返すWindows向け補助ツールです。物理マウスを動かさない軽量なバックグラウンド構成で、画面座標やモニター解像度に依存せず操作します。メイン画面はiOS/iPadOS標準アプリの情報階層を参考にしたネイティブWindows UI、登録画面はゲーム上に重なるクリック透過HUDです。

> 使用するサーバーの利用規約・ルールを必ず確認してください。本ソフトウェアの使用によるアカウント制限、データ損失、そのほかの損害について作者は責任を負いません。

## 対応している作業

| モード | 検出する表示 | 標準周期 | 補足 |
|---|---|---:|---|
| 採掘 | `鉱石を採掘する` | 石の再出現を検知 | 石が戻ったときだけ押します |
| 石洗い | `石を洗う` | 9秒 | 後退を抑える前進補正付きです |
| 砂金採り | `砂金採りトレイ` | 6秒 | 連続未検出時の安全な自動位置補正付きです |

開始・停止キーは設定画面から変更できます。初期値は開始 `F8`、停止 `F9` です。詳しい手順は [AI採掘機_使い方.txt](docs/AI採掘機_使い方.txt) を参照してください。

## v6.2.0の主な変更

- ox_inventoryのプレイヤー側 `weight` と `maxWeight` を使い、残り重量を主条件として自動収納を開始します。設定画面で開始値を250～20000gの範囲から変更でき、全スロット使用は補助の安全条件です。
- 起動時にFiveMのウィンドウとプロセスID、対象・インベントリNUIのセッションを固定します。FiveM終了、プロセス置換、サーバー再起動・再接続に相当するセッション変更、または接続確認の連続失敗時は入力を解放して安全停止します。
- 登録した車両後部に着いたあと、原点から前後左右・斜めへ短く出て戻る境界付きの星形探索を追加しました。少しの駐車位置ずれには追従できますが、任意位置の車両探索や経路再計算ではありません。
- 車両登録をルート形式3へ更新しました。矢印キーの視点はDevConの直接視点コマンドとして記録・再生し、停止・中断時は旧方式を含む全視点入力を解放します。
- 白基調のinset grouped list、単一アクセント、システムフォント、暗色の状態カードを中心に、ネイティブUIと登録HUDを整理しました。Apple製品やiOSそのものを再現・偽装するUIではありません。

## 車両収納（v6.2.0）

所持品の残り重量が設定値以下になると、登録済みの車両荷台へ今回増えた採集品だけを収納し、作業位置へ戻って再開します。初回はライブのFiveM画面で登録が必要です。

1. 作業対象の前で「車両」画面の「車両とルートを登録」を選びます。
2. HUDの「開始待ち」で全キーを離してEnterを押します。記録開始後、W/A/S/Dで車両後部へ歩き、矢印キーで視点を合わせます。到着したら全キーを離してEnterを押します。
3. `ストレージを開く`、`トランクを開く`、または`荷台を開く`を構造的に検出します。開いたインベントリが車両後部の `trunk` であることを確認し、そのIDと種類を登録します。
4. 同じ操作で作業位置へ戻る復路と視点を記録します。元の作業ボタンを再検出できた場合だけ次へ進みます。
5. 保存前に、記録した往路で同じ荷台を照合し、復路で作業ボタンへ戻れるか一往復テストします。すべて成功した場合だけ新しい登録へ置き換えます。

v6.1.0以前のルート形式1・2は自動再生しません。更新後に「安全更新が必要」または「旧方式のルート」と表示された場合は、必ずv6.2.0で車両と往復ルートを登録し直してください。

容量は画像や空きマスの数ではなく、サーバーがNUIへ渡したプレイヤーインベントリの `weight` / `maxWeight` を優先して判断します。残り重量が「自動収納を始める残り重量」以下になった場合が主な開始条件で、全スロット使用も補助条件です。開始時点ですでに容量不足なら作業を始めず、取得エラー中も追加採集を止め、3回連続で確認できなければ安全停止します。

収納時は開始時点の所持品をスロット・名前・正規化メタデータ・数量ごとに基準化し、以後プラスになったアイテムだけを移します。開始前から持っていた道具・食料や、同名でも状態の異なる品は保護されます。移動先では登録済みの荷台IDと種類 `trunk` が完全一致すること、候補が1つだけであることを確認してから収納します。グローブボックスや別車両、候補が複数ある状態には収納しません。

登録地点で荷台が見つからない場合は、前後左右・斜めの短い8位置、同じ8位置と直接視点操作の組み合わせ、少し長い前後左右4位置の順で、最大20回の小範囲探索を行います。各失敗経路は逆再生して探索原点へ戻るため、探索によるずれを累積させません。一致した荷台からも補正分を戻してから登録済みの復路を再生します。これは小さな位置・視点ずれだけを吸収する限定探索であり、移動した車両を画面認識して追跡する機能ではありません。

### 視点操作の注意

登録中の矢印キーは、ルート再生時に `+look_up` / `+look_down` / `+look_left` / `+look_right` としてFiveMへ送られます。コマンド生成と全入力解放は自動テストしていますが、実際の視点反応はFiveMクライアント、サーバー資源、入力設定の影響を受けるため、オフラインのビルドテストだけでは保証できません。登録時の往復テストで荷台と作業対象の両方を確認できない場合は保存せず、実環境で視点が動くことを確認してから使ってください。

車両は登録位置の近くに駐車し、往復経路を障害物のない状態に保ってください。任意経路探索、車両所有者の判定、大きく移動・置換された車両の追跡、サーバーが別名・別方式で実装した荷台には対応しません。インベントリ取得、経路移動、荷台一致、収納、復路、または復帰先の作業ボタン確認に失敗した場合は、誤操作を避けるため安全停止します。

## 接続監視と安全停止

開始前にFiveMのプロセスと対象・インベントリNUIを確認し、開始後は標準3.5秒ごとに同じウィンドウ、同じプロセスID、同じNUIセッションであるか監視します。セッション識別子が変わった場合はサーバー再起動・再接続として即時停止します。一時的に読めない間は作業や移動を行わず再確認し、3回連続で失敗すると停止します。

登録時の往復テスト、通常の往復・荷台探索、砂金採りの位置補正で移動ルートを再生するときは、開始時と累積約2.5秒ごとのステップ境界で移動・視点入力をいったん解放し、開始時のNUI session epochと照合します。車両到着直後、収納直前、収納後に入力を解放して復路へ入る前にも照合します。不一致時はそのルートを打ち切り、車両処理では次の移動・収納に進まず安全停止し、砂金補正では同じ未検出中の追加移動を行いません。

この監視はサーバー固有の再起動通知を読むものではありません。FiveM/NUIが同一セッションのまま残る特殊な切断状態など、すべてのサーバー状態を保証するものではないため、停止キーを常に使用できる状態にしてください。

## UIの基準

メイン画面はWindowsネイティブ部品の範囲で、iOS/iPadOSの設定系画面にある情報階層、inset grouped list、タイポグラフィ、余白、状態表現を参考にしています。実行中の暗色状態カードと登録HUDはLive Activitiesの「重要な状態と操作だけを短く示す」考え方を取り入れています。偽のステータスバー、端末外枠、Appleロゴは使用しません。

参考: [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/)、[Typography](https://developer.apple.com/design/human-interface-guidelines/typography)、[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)、[Live Activities](https://developer.apple.com/design/human-interface-guidelines/live-activities)

## インストール

1. [Releases](https://github.com/kanzakideath/fivemstonefarm/releases) から最新の `AI-Miner-vX.Y.Z.zip` を取得します。
2. ZIPを任意の書き込み可能なフォルダーへ展開します。
3. `AI採掘機.exe` を起動します。

配布物のハッシュは各Releaseの `SHA256SUMS.txt` で確認できます。設定は実行ファイルと同じ場所の `AI採掘機.ini` に保存され、更新時にも維持されます。

## 安全な自動更新

更新先は `kanzakideath/fivemstonefarm` のGitHub Releasesに固定されています。起動時の自動確認または「アップデート」画面から新しい版を確認でき、利用可能な場合は画面とサイドバーへ通知します。アプリは次のすべてを確認できた場合だけ更新します。

- `update-manifest.json` が、アプリに埋め込まれたECDSA P-256公開鍵で検証できること
- マニフェストの製品名・バージョン・配布URLが許可された形式と一致すること
- ダウンロードした実行ファイルのサイズとSHA-256がマニフェストと一致すること
- 置換後の実行ファイルが自己検証に成功すること

署名または検証に失敗した更新は適用せず、置換失敗時は以前の実行ファイルへロールバックします。秘密の署名鍵はリポジトリへ保存せず、GitHubの保護された `release` Environmentにだけ登録します。

## ソースからビルド

必要なもの:

- Windows 10 / 11（64 bit）
- PowerShell 7.2以上（Release作成時）
- .NET Framework 4.x のC#コンパイラー
- Git

通常のビルド:

```powershell
pwsh -File .\scripts\Build.ps1 -Version 6.2.0
```

初回は公式配布元からAutoHotkey v2.0.26とAhk2Exe v1.1.37.02a2を取得し、公開されているSHA-256を検証します。ダウンロード先の `tools/` と `.cache/` はGit管理外です。

成果物は `dist/ai-miner-win-x64.exe` です。ビルドはC#ヘルパーのcapability/self-test、偽DevConによる移動・直接視点・全入力解放コマンド検証、完成した実行ファイルの `--validate` / `--smoke-test` を実行します。偽DevConテストはコマンド生成を検証するもので、実FiveM内のカメラ移動を再現するものではありません。

## Releaseを公開する

1. GitHubリポジトリの Environment に `release` を作成します。
2. `release` Environment secret `UPDATE_SIGNING_KEY_PKCS8_B64` に、ECDSA P-256秘密鍵のPKCS#8 DERをBase64化した値を登録します。
3. ソース内の `AppVersion` と同じタグを作成してpushします。

```powershell
git tag v6.2.0
git push origin v6.2.0
```

`.github/workflows/release.yml` はタグ `vX.Y.Z` のみを受け付け、ビルド・自己検証・署名・署名再検証を行った後に次を公開します。

- `ai-miner-win-x64.exe`
- `AI-Miner-vX.Y.Z.zip`
- `update-manifest.json`
- `update-manifest.sig`
- `SHA256SUMS.txt`

署名秘密鍵から導出した公開鍵がアプリ内の固定公開鍵と一致しない場合、Release処理は停止します。
