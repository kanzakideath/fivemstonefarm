# AI採掘機 v9.0.0

FiveMの対象UIを構造的に検出し、採掘・石洗い・砂金採りを繰り返すWindows向け補助ツールです。バックグラウンド操作では、物理マウスや別アプリのフォーカスを奪わず、画面座標やモニター解像度にも依存しません。

> 使用するサーバーのルールと管理者の許可を必ず確認してください。DLL注入、プロセスメモリ読取り、アンチチート回避は行いません。

## 対応作業

| モード | 検出表示 | 標準動作 |
|---|---|---|
| 採掘 | `鉱石を採掘する` | 進捗完了と次の石の準備を検知し、使用可能になるとすぐ再実行 |
| 石洗い | `石を洗う` | 進捗完了を検知し、1度だけ前進補正して次の対象を即選択 |
| 砂金採り | `砂金採りトレイ` | 進捗完了と次の対象の準備を検知し、未検出時だけ境界付き補正 |

すべての作業で進捗UIの開始と完了、対象の再表示を監視します。サーバー側の採掘・石洗い・砂金採り自体の所要時間を短縮する機能ではなく、完了後に重なっていた固定待機をなくします。石洗いの対象が同時に複数表示された場合は、使用可能な候補を1つに絞って選択します。

開始・停止キーは変更できます。初期値は開始 `F8`、停止 `F9` です。

## Stone Metagame

サイドバーの「STONE」から、採掘実績と連動するMetagameを開けます。

- HOME: Mining Level、Affinity、Ticket、次の目標をリアルタイム表示
- GACHA: 単発・10連、3種類の10連演出、Pickup・保証・Pity、履歴と統計
- COLLECTION: 入手済みアイテムと重複状況
- ACHIEVEMENTS: 条件達成と解除状況
- PROFILE: 名前、アイコン、称号、フレームの編集とライブプレビュー

カウント対象は、採掘後のインベントリ差分で石の取得を確認できた瞬間だけです。1回の確認済み採掘報酬を1回として一意なイベントで通知し、作業開始、クリック、アニメーション開始、失敗、石洗い、砂金採り、自動収納、復帰操作では増えません。Metagame処理はFarmループと分離されているため、ガチャ・実績・保存処理を待って次の作業が遅れる構成ではありません。

Metagameの状態はFarm設定と分離し、`%LOCALAPPDATA%\AI採掘機\metagame\state.json` へschema v2として原子的に保存します。同じ場所の `state.json.bak` から破損時に復旧します。

## 車両登録と自動収納

サーバー側へのファイル導入、車両座標、W/A/S/D・矢印キーの記録は使いません。

1. 「車両」で「車両を登録」を押します。
2. FiveMへ戻り、登録したい車両のストレージを通常どおり一度開きます。
3. アプリが `trunk` の不透明なストレージIDを検出し、PC内の設定へ保存します。
4. 採掘・石洗い・砂金採りの開始時に所持品を基準化します。
5. 最新の所持重量率、次の報酬を受け取れる残り重量、空きスロット数を確認し、いずれかが設定した安全域へ達すると新しい作業を止めます。
6. 近距離で視点と短い移動を境界付き探索し、同じストレージIDの荷台だけを開きます。
7. 開始後に増えた持ち物だけを収納し、プレイヤー所持品の実減少と再開可能な空き容量を確認してから往路を逆再生します。
8. 作業地点へ戻った後、実際の次回報酬を確認できた場合だけ通常のFarm状態へ戻ります。

制御は `IDLE`、`FARMING`、`INVENTORY_CHECK`、`INVENTORY_FULL`、`STOPPING_FARM`、`OPENING_STORAGE`、`STORING`、`VERIFY_STORAGE`、`RETURNING_TO_FARM`、`RESUMING_FARM`、`RECOVERY`、`ERROR` の単一状態機械です。入力・収納・復帰・復旧が同時に走らないよう、実行世代とtask IDでも古い処理を拒否します。

別車両のIDが開いた場合は何も移しません。収納を確認できない間は車両側に留まって設定回数まで再試行します。途中状態が不明になった場合は入力をすべて解放して `RECOVERY` へ入り、最新所持品を再取得します。まだ容量不足なら収納へ、十分に空いていれば作業地点への復帰へ進みます。車両が近くにない、探索範囲外へ移動した、荷台が満杯、入力復元や作業位置の再検出に繰り返し失敗した場合は `ERROR` で安全停止します。サーバー側APIを使わないため、マップ上の任意の遠距離車両を追跡する機能ではありません。

開始時点ですでに収納しきい値を超えている場合は、今回のFarmで増えた品と既存の食料・道具を判別できないため、全搬出せず `UNTRUSTED_STORAGE_BASELINE` で安全停止します。手動で次の報酬を受け取れる空きを作ってから開始してください。

## 視点固定と自動食事

バックグラウンド作業中は、採掘・石洗い・砂金採りの各試行前に下向き視点を定期的に再適用します。物理マウスは動かしません。「設定」の「作業位置と視点を自動補正」で位置補正と一緒に切り替えられます。

作業対象が一定時間見つからない場合は、入力状態をリセットして視点と対象を再取得します。確認済み報酬がWatchdog時間内に増えない場合も復旧へ移り、無反応のままクリックだけを繰り返しません。「詳細デバッグ表示」を有効にすると、状態名、task ID、再試行、検出理由をHUDとログで追跡できます。通常は負荷と画面占有を抑えるため無効です。

対象選択から進捗完了までを1つの軽量helperで連続監視し、完了時の接続確認も同じCDP接続で済ませます。短い視点補正も接続を使い回し、同じ安全確認を何度も起動する待ち時間を省きます。容量は報酬反映後に確認し、速度のために満量判定を省略しません。

稼働中にFiveMを前面へ戻すと、作業種別・現在状態・操作回数・残り重量・収納回数を示すクリック透過HUDがクライアント上部に表示されます。別アプリへ切り替えると自動で隠れます。ウィンドウ表示とボーダーレス全画面に対応します。

自動食事は既定でホットバースロット `1` を使い、「設定」でオン／オフとスロット `1`～`5` を変更できます。FiveMが前面なら空腹ゲージを複数回確認し、裏画面でゲージを読めない間は開始1分後、その後8分ごとの保守的なフォールバックを使います。指定スロットへ実際に使用できる食べ物を置いてください。使用前後の同スロット個数が減った場合だけ成功として記録し、3回続けて確認できなければ食べずに採集し続けないよう安全停止します。

## 導入

1. [Releases](https://github.com/kanzakideath/fivemstonefarm/releases) から `AI-Miner-v9.0.0.zip` を取得します。
2. 書き込み可能なフォルダーへ展開します。
3. `AI採掘機.exe` を起動します。
4. 「設定」でバックグラウンド操作、キー、視点補正、自動食事・食料スロット、自動収納のしきい値を確認します。

設定は同じフォルダーの `AI採掘機.ini` に保存され、自動更新後も維持されます。

## UI

従来のAutoHotkey標準ウィジェット画面は廃止しました。バックエンド処理は維持し、ローカルWebView2上のFramework7 iOSテーマで、概要・車両・STONE・設定・アップデートを共通のサイドバー、グループ化リスト、選択シート、スイッチ、主操作ボタンへ置き換えています。STONE内のHOME、GACHA、COLLECTION、ACHIEVEMENTS、PROFILEも同じオフラインUIへ統合されています。UI資産はEXEへ埋め込み、通常起動時にCDNへ接続しません。

## 安全停止と更新

FiveMのウィンドウ/PIDと対象・インベントリNUIのセッションを固定し、FiveM終了、プロセス置換、サーバー再起動・再接続相当の変化、連続した読取り失敗を検知すると入力を解放して停止します。自動再ログインは行いません。

更新先はこのリポジトリのGitHub Releasesに固定されています。製品名・URL・サイズ・SHA-256・ECDSA署名・置換後自己検証がすべて一致した場合だけ更新します。

## ソースからビルド

必要なもの:

- Windows 10 / 11（64 bit）
- PowerShell
- Node.js 20以降
- .NET SDK 8以降と .NET Framework参照アセンブリ
- Git

```powershell
pwsh -File .\scripts\Build.ps1 -Version 9.0.0
```

ビルドは依存ロック、Web UI、WebView2ホスト、FiveM bridge、更新helper、完成EXEの自己テストを実行します。

## 確認上の制約

v9.0.0の統合テストと模擬Farm状態試験は、実際のFiveMサーバーへ入力しないローカル環境で実行できます。一方、サーバー固有のox_inventory表示、車両配置、通信遅延を含む実地動作は利用先ごとに異なるため、配布前に許可されたFiveM環境での確認が必要です。
