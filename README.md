# AI採掘機 v6.0.1

FiveM上の対象ボタンを構造的に検出し、採掘・石洗い・砂金採りを繰り返すWindows向け補助ツールです。軽量なバックグラウンド構成のため物理マウスを動かさず、画面解像度に依存しない操作を行います。iOS風のレスポンシブなWindows UIから、作業・車両・設定・更新を操作できます。

> 使用するサーバーの利用規約・ルールを必ず確認してください。本ソフトウェアの使用によるアカウント制限、データ損失、そのほかの損害について作者は責任を負いません。

## 対応している作業

| モード | 検出する表示 | 標準周期 | 補足 |
|---|---|---:|---|
| 採掘 | `鉱石を採掘する` | 石の再出現を検知 | 石が戻ったときだけ押します |
| 石洗い | `石を洗う` | 9秒 | 後退を抑える前進補正付きです |
| 砂金採り | `砂金採りトレイ` | 6秒 | 連続未検出時の安全な自動位置補正付きです |

開始・停止キーは設定画面から変更できます。初期値は開始 `F8`、停止 `F9` です。詳しい手順は [AI採掘機_使い方.txt](docs/AI採掘機_使い方.txt) を参照してください。

v6.0.1では、砂金採りボタンを12秒間連続で検出できない場合に、前後・左右を小さく探る最大6段階の位置補正を行います。各段階の直後にボタンを再検出し、成功すると補正状態を自動でリセットします。6段階で復帰できない場合はそれ以上移動せず、手動で位置を調整するまで待機するため、無制限に歩き続けません。また、装飾面が操作部品を遮らないようUIのクリック処理を修正し、設定や各ボタンを確実に操作できるようにしました。

## 車両収納（v6.0.1）

採掘中に持ち物の空き容量が少なくなると、登録済みの車両ストレージへ今回増えた採集品だけを収納し、作業位置へ自動で戻って再開できます。初回はライブのFiveM画面で登録が必要です。

1. 作業対象の前で「車両」画面の「車両とルートを登録」を選びます。
2. 表示される登録オーバーレイに従い、カメラを動かさず W/A/S/D だけで車両後部まで歩きます。往路はキー操作ごとに別々に記録されます。
3. `ストレージを開く` が確認できる車両後部で、実際に開いたストレージの正確な ID と種類を取得します。
4. 同様にカメラを動かさず W/A/S/D だけで作業位置へ戻り、復路を別途記録します。元の作業ボタンを再確認できたときだけ登録が完了します。

容量はインベントリの表示画像ではなく構造化データから読み取ります。収納時は開始時点の所持品をスロット・名前・メタデータ・数量ごとに基準化し、以後プラスになったアイテムだけを移します。そのため、開始前から持っていた道具・食料や、同名でも状態の異なる品は保護されます。移動先では登録済みのストレージ ID と種類が完全一致することを確認してから収納します。

車両は登録時と同じ場所に駐車したままにし、往復経路を障害物のない状態に保ってください。任意の経路探索、車両の所有者検出、移動・置換された車両の追跡には対応していません。インベントリ取得、経路移動、ストレージ一致、収納、復路、または復帰先の作業ボタン確認に失敗した場合は、誤操作を避けるため安全停止します。

## インストール

1. [Releases](https://github.com/kanzakideath/fivemstonefarm/releases) から最新の `AI-Miner-vX.Y.Z.zip` を取得します。
2. ZIPを任意の書き込み可能なフォルダーへ展開します。
3. `AI採掘機.exe` を起動します。

配布物のハッシュは各Releaseの `SHA256SUMS.txt` で確認できます。設定は実行ファイルと同じ場所の `AI採掘機.ini` に保存され、更新時にも維持されます。

## 安全な自動更新

更新先は `kanzakideath/fivemstonefarm` のGitHub Releasesに固定されています。アプリは次のすべてを確認できた場合だけ更新します。

- `update-manifest.json` が、アプリに埋め込まれたECDSA P-256公開鍵で検証できること
- マニフェストの製品名・バージョン・配布URLが許可された形式と一致すること
- ダウンロードした実行ファイルのサイズとSHA-256がマニフェストと一致すること
- 置換後の実行ファイルが自己検証に成功すること

署名または検証に失敗した更新は適用しません。秘密の署名鍵はリポジトリへ保存せず、GitHubの保護された `release` Environmentにだけ登録します。

## ソースからビルド

必要なもの:

- Windows 10 / 11（64 bit）
- PowerShell 7.2以上（Release作成時）
- .NET Framework 4.x のC#コンパイラー
- Git

通常のビルド:

```powershell
pwsh -File .\scripts\Build.ps1 -Version 6.0.1
```

初回は公式配布元から次のツールを取得し、公開されているSHA-256を検証します。ダウンロード先の `tools/` と `.cache/` はGit管理外です。

- AutoHotkey v2.0.26
- Ahk2Exe v1.1.37.02a2

成果物は `dist/ai-miner-win-x64.exe` です。ビルドはC#ヘルパーのcapabilityテストと、完成した実行ファイルの `--validate` / `--smoke-test` を実行します。

## Releaseを公開する

1. GitHubリポジトリの Environment に `release` を作成します。
2. `release` Environment secret `UPDATE_SIGNING_KEY_PKCS8_B64` に、ECDSA P-256秘密鍵のPKCS#8 DERをBase64化した値を登録します。
3. ソース内の `AppVersion` と同じタグを作成してpushします。

```powershell
git tag v6.0.1
git push origin v6.0.1
```

`.github/workflows/release.yml` はタグ `vX.Y.Z` のみを受け付け、ビルド・自己検証・署名・署名再検証を行った後に次を公開します。

- `ai-miner-win-x64.exe`
- `AI-Miner-vX.Y.Z.zip`
- `update-manifest.json`
- `update-manifest.sig`
- `SHA256SUMS.txt`

署名秘密鍵から導出した公開鍵がアプリ内の固定公開鍵と一致しない場合、Release処理は停止します。
