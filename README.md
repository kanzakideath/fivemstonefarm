# AI採掘機 v9.1.15

FiveMの対応UIを検出し、採掘・石洗い・砂金取りを繰り返すWindows向け補助ツールです。**サーバー側への追加リソース導入は不要**です。既存の対応NUIを使うため、すべてのサーバーで同じ動作になる保証はありません。

> 使用するサーバーのルールと管理者の許可に従ってください。ゲームメモリ読取り、DLL/ASI注入、アンチチート回避は追加しません。


## 今回の変更

徒歩ルート・自動前進・画像による位置合わせ・強制下向き・視点復旧を、実行中のアプリから使用しない方式へ変更しました。旧設定で補正ON、徒歩ルートVerifiedになっていても再生しません。キー入力時間を増やす修正ではありません。

**これはゲーム内座標やアニメーションを固定する機能ではありません。** EXEが移動・視点入力を送らなくてもゲーム側の動作で位置が変わる場合はあります。その場合は追加移動せず自動再開待ちになり、操作範囲が戻れば再開します。範囲が戻らない限り作業は進みません。「位置が絶対に変化しない」「全サーバーで無限に継続する」とは保証しません。

## 開始と作業ループ

石掘り・石洗い・砂金取りの全モードを荷台前専用にします。開始時に同じ場所で「作業 → 登録した荷台ID → 荷台画面を閉じる → 作業」を実確認し、作業とストレージの両項目が同時に利用可能なことを確認して開始します。開始確認はアイテムを転送しません。未洗浄石0では初回の両ボタン確認ができないため、石洗いの開始時は未洗浄石を持ってください。

各作業前にも、進捗の終了・所持品画面の閉鎖・両項目の利用可能性・同一接続を確認します。クリックと同じ評価内でもストレージ項目を再確認して、作業ボタンだけを1回選びます。画像の一致度による前進・逆方向停止・固定画像への収束待ちは行いません。

実報酬確認 → 次の作業可否確認 → 次の作業、を繰り返します。石洗いの手持ち石0が確認済みなら洗浄ボタンを要求せず、その場で成果収納 → 石補充 → 荷台画面を閉じる → 次の洗浄へ進みます。石掘り・砂金は容量のしきい値でその場収納を行います。自動収納OFFを勝手にONにはしません。

収納は登録荷台ID、今回確認済みの成果、数量・metadata、双方の所持品変化と操作結果を照合します。未確定な転送の再送禁止、荷台満杯時の停止と、確定した石在庫0での補充待ち、既存所持品の保護は維持します。停止後の再開始時に既存所持品まで一括で勝手に収納しません。

## 設定・移行

1. F9で停止して更新します。自分のINIやセーブを削除する必要はありません。
2. 左の「荷台前の設定」で荷台を登録し、「この位置で近接収納を確認（歩かない）」を実行します。両方のボタンが同時に使える位置で確認してください。
3. 自動収納・補充をONにし、FiveMを前面にしてF8で開始します。開始時にも登録荷台を確認し直します。徒歩記録・前進時間の調節は不要です。

旧徒歩記録の画像ファイルは破壊しませんが、この版から呼び出しません。近接確認が成功したときだけ同モードのメタデータを更新します。補正の設定値は常に無効扱いで保存し、UIに補正を有効化する操作はありません。サーバー側導入やメモリ読み取りは追加しません。

## 診断

既存の診断ZIPに `STATIONARY_WAIT`、`STATIONARY_AUTO_RESUME` を記録します。旧移動処理が呼ばれた場合は送信前に `STATIONARY_MOTION_REJECTED` として拒否します。移動入力を送っていないことと、ゲーム内位置が変わっていないことは別です。診断ZIPの自動送信はありません。

## 検証範囲

新しい固定ポリシー・3モードの続行/停止/石0補充判定は完成EXEの自己テストに含めています。旧設定がONでも移動コマンド・ヘルパー起動・相対マウス入口を拒否する実行試験、同一JS評価の荷台/作業クリック試験、旧版設定保持と更新試験、4幅の設定UIを検証対象にしています。

既存の移動ヘルパーは履歴互換のソース/試験として残りますが、本体からの実行入口は閉じています。古いヘルパー単体の試験成功を、新しい非移動モードの実FiveM成功とは扱いません。実FiveMの長時間稼働・サーバー由来の後退・全端末での収納成功率は未測定です。
