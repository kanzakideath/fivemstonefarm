# AI採掘機 v9.1.1

FiveMの対象UIを構造的に検出し、採掘・石洗い・砂金採りを繰り返すWindows向け補助ツールです。対象の検出と選択は画面座標やモニター解像度に依存せずバックグラウンドで行います。GTAの視点は、FiveMが前面なら相対マウス入力、バックグラウンド動作中ならFiveMのDevCon入力だけで補正し、作業中の別アプリへマウスやキーを送りません。

> 使用するサーバーのルールと管理者の許可を必ず確認してください。DLL注入、プロセスメモリ読取り、アンチチート回避は行いません。

## 対応作業

| モード | 検出表示 | 標準動作 |
|---|---|---|
| 採掘 | `鉱石を採掘する` | 進捗完了と次の石の準備を検知し、使用可能になるとすぐ再実行 |
| 石洗い | `石を洗う` | 毎回真下へ視点を合わせて対象を再確認し、実報酬後は1.2秒の後退停止待ちと1度だけの前進補正を実行 |
| 砂金採り | `砂金採りトレイ` | 毎回真下へ視点を合わせて対象を再確認し、進捗完了後すぐ再実行 |

すべての作業で進捗UIの開始と完了、実際のインベントリ増加、対象の再表示を監視します。サーバー側の採掘・石洗い・砂金採り自体の所要時間を短縮する機能ではありません。石洗いだけは、報酬反映後も約1秒続く後退が止まるまで既定1.2秒の専用静止状態に入り、その間は移動・視点・クリック入力を送りません。静止後に前進補正を1度だけ実行し、次の試行では再び真下へ合わせてから `石を洗う` を確認します。同じ対象が複数表示された場合は、使用可能な候補を1つに絞ります。

開始・停止キーは変更できます。初期値は開始 `F8`、停止 `F9` です。

## Stone Metagame

サイドバーの「STONE」から、採掘実績と連動するMetagameを開けます。

- HOME: Mining Level、Affinity、Ticket、次の目標をリアルタイム表示
- GACHA: 単発・10連、3種類の10連演出、Pickup・保証・Pity、履歴と統計
- COLLECTION: 入手済みアイテムと重複状況
- ACHIEVEMENTS: 条件達成と解除状況
- PROFILE: 名前、アイコン、称号、フレームの編集とライブプレビュー

カウント対象は、採掘・石洗い・砂金採りの完了後にインベントリの重量またはアイテム数が実際に増えた瞬間だけです。1回の確認済み作業報酬をSTONE 1回としてモード入りの一意なイベントで通知し、作業開始、クリック、アニメーション開始、失敗、自動収納、復帰操作では増えません。同じイベントの再送は二重加算されません。v9.0.2への初回更新時は、更新したEXEと同じフォルダーに残る診断ログの確認済み報酬だけを一度取り込みます。移行済み情報もそのフォルダー単位で保持するため、空の新規展開版を先に起動しても旧フォルダーの履歴を無効にしません。削除済みの古いログや推定回数は加算しません。Metagame処理はFarmループと分離されているため、ガチャ・実績・保存処理を待って次の作業が遅れる構成ではありません。

確認済み報酬は、通常の診断ログとは別の `%LOCALAPPDATA%\AI採掘機\verified-reward-wal.tsv` へ先に同期保存してから送信キューへ入ります。保存途中の終了、F9直後のF8、Host停止があっても同じイベントIDで回収し、送信済みなら再加算しません。Metagameの状態はFarm設定と分離し、`%LOCALAPPDATA%\AI採掘機\metagame\state.json` へschema v2として原子的に保存します。同じ場所の `state.json.bak` から破損時に復旧します。

## 車両登録と自動収納

サーバー側へのファイル導入、車両座標、W/A/S/D・矢印キーの記録は使いません。

1. 「車両」で「車両を登録」を押します。
2. FiveMへ戻り、登録したい車両のストレージを通常どおり一度開きます。
3. アプリが `trunk` の不透明なストレージIDを検出し、PC内の設定へ保存します。
4. 採掘・石洗い・砂金採りの開始時に所持品を基準化します。
5. 最新の所持重量率、次の報酬を受け取れる残り重量、空きスロット数を確認し、いずれかが設定した安全域へ達すると新しい作業を止めます。満量を確認した後は、消えている可能性がある作業ボタンやカメラ状態を出発条件にしません。
6. 近距離で視点と短い移動を境界付き探索し、開いた荷台のストレージIDが登録値と一致した場合だけ到着とします。
7. 開始後に増えた持ち物だけを収納し、プレイヤー側の実減少と荷台側の実増加を確認します。石洗いでは、その後に実際の洗浄で特定した未洗浄石だけを、最新の重量・空きスロット・作業用余裕から計算した上限まで取り出し、個数の実増加を確認します。
8. インベントリを閉じたことと逆経路を確認して作業地点へ戻り、作業ボタンの再取得後、実際の次回報酬を確認できた場合だけ通常のFarm状態へ戻ります。

制御は `IDLE` / `FARMING` に加え、`CHECKING_INVENTORY` → `NEED_STORAGE` → `STOPPING_FARM` → `LOCATING_TRUCK` → `MOVING_TO_TRUCK` → `VERIFY_TRUCK_REACHED` → `OPENING_STORAGE` → `STORING_OUTPUTS` → `VERIFY_STORAGE` → `REFILLING_INPUT` → `VERIFY_REFILL` → `LOCATING_FARM` → `RETURNING_TO_FARM` → `VERIFY_FARM_REACHED` → `RESUMING_FARM` → `VERIFY_FARM_RESUMED` の収納経路、洗浄後の `WASH_SETTLING` → `WASH_CORRECTING` → `WASH_VERIFYING`、そして `RECOVERY` / `ERROR` を持つ23状態の明示的な単一状態機械です。入力・収納・補充・復帰・復旧が同時に走らないよう、実行世代とtask IDでも古い処理を拒否します。

別車両のIDが開いた場合は何も移しません。収納を確認できない間は車両側に留まって設定回数まで再観測します。途中状態が不明になった場合は入力と古いhelperを止めて `RECOVERY` へ入り、最新所持品から「収納・補充・帰還」の未完了段階を選び直します。同じ復旧を無限には繰り返さず、安全な再開を1回試しても確認できなければ `ERROR` で停止します。容量不足または異常停止時はWindowsの通知音でも知らせます。車両が近くにない、探索範囲外へ移動した、荷台が満杯、入力復元や作業位置の再検出に失敗した場合も安全停止します。サーバー側APIを使わないため、マップ上の任意の遠距離車両を追跡する機能ではありません。

移動要求を送信した後にFiveM側の応答が途切れ、収納結果を確定できない場合は、同じ要求を自動再送せず `AMBIGUOUS_TRANSFER` で停止します。この警告後に手動再開する場合は、先にプレイヤー所持品と登録した荷台の両方を確認してください。

開始時点ですでに収納しきい値を超えている場合は、今回のFarmで増えた品と既存の食料・道具を判別できないため、全搬出せず `UNTRUSTED_STORAGE_BASELINE` で安全停止します。手動で次の報酬を受け取れる空きを作ってから開始してください。

## 視点固定と自動食事

石洗いと砂金採りは、各試行の直前に視点を真下のクランプまで入力し、対象ボタンを実際に再検出してからクリックします。FiveMが前面なら相対マウス入力、バックグラウンド動作時はFiveMのDevCon入力だけを使うため、別アプリのカーソルやキーを動かしません。採掘は対象を実際に見失った場合だけ下向き視点を復旧します。「設定」の「作業位置と視点を自動復旧」で切り替えられます。

作業対象が一定時間見つからない場合は、入力状態をリセットして視点と対象を再取得します。確認済み報酬がWatchdog時間内に増えない場合も復旧へ移り、無反応のままクリックだけを繰り返しません。「詳細デバッグ表示」を有効にすると、状態名、task ID、再試行、検出理由をHUDとログで追跡できます。通常は負荷と画面占有を抑えるため無効です。

対象選択から進捗完了までを1つの軽量helperで連続監視し、完了時の接続確認も同じCDP接続で済ませます。視点入力を送れたことと復旧できたことを区別し、作業ボタンを再検出した場合だけ成功として表示します。容量は報酬反映後に確認し、速度のために満量判定を省略しません。

稼働中にFiveMを前面へ戻すと、作業種別・現在状態・操作回数・残り重量・収納回数を示すクリック透過HUDがクライアント上部に表示されます。別アプリへ切り替えると自動で隠れます。ウィンドウ表示とボーダーレス全画面に対応します。

自動食事は既定でホットバースロット `1` を使い、「設定」でオン／オフとスロット `1`～`5` を変更できます。FiveMが前面なら空腹ゲージを複数回確認し、裏画面でゲージを読めない間は開始1分後、その後8分ごとの保守的なフォールバックを使います。指定スロットへ実際に使用できる食べ物を置いてください。使用前後の同スロット個数が減った場合だけ成功として記録し、3回続けて確認できなければ食べずに採集し続けないよう安全停止します。

## 導入

1. [Releases](https://github.com/kanzakideath/fivemstonefarm/releases) から `AI-Miner-v9.1.1.zip` を取得します。
2. 書き込み可能なフォルダーへ展開します。
3. `AI採掘機.exe` を起動します。
4. 「設定」でバックグラウンド操作、キー、視点補正、自動食事・食料スロット、自動収納のしきい値を確認します。

設定は同じフォルダーの `AI採掘機.ini` に保存され、自動更新後も維持されます。

## UI

従来のAutoHotkey標準ウィジェット画面は廃止しました。バックエンド処理は維持し、ローカルWebView2上のFramework7 iOSテーマで、概要・車両・STONE・設定・アップデートを共通のサイドバー、グループ化リスト、選択シート、スイッチ、主操作ボタンへ置き換えています。STONE内のHOME、GACHA、COLLECTION、ACHIEVEMENTS、PROFILEも同じオフラインUIへ統合されています。UI資産はEXEへ埋め込み、通常起動時にCDNへ接続しません。

## 安全停止と更新

FiveMのウィンドウ/PIDと対象・インベントリNUIのセッションを固定し、FiveM終了、プロセス置換、サーバー再起動・再接続相当の変化、連続した読取り失敗を検知すると入力を解放して停止します。自動再ログインは行いません。

更新先はこのリポジトリのGitHub Releasesに固定されています。製品名・URL・サイズ・SHA-256・ECDSA署名・置換後自己検証がすべて一致した場合だけ更新します。

## ソースからビルド

必要なもの:

- Windows 10 / 11（64 bit）
- PowerShell
- Node.js 20以降
- .NET SDK 8以降と .NET Framework参照アセンブリ
- Git

```powershell
pwsh -File .\scripts\Build.ps1 -Version 9.1.1
```

ビルドは依存ロック、Web UI、WebView2ホスト、FiveM bridge、更新helper、完成EXEの自己テストを実行します。

## 確認上の制約

v9.1.1の統合テストと模擬Farm状態試験は、実際のFiveMサーバーへ入力しないローカル環境で実行できます。一方、サーバー固有のox_inventory表示、車両配置、通信遅延を含む実地動作は利用先ごとに異なるため、配布前に許可されたFiveM環境での確認が必要です。
