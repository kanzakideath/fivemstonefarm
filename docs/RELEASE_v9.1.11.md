# AI採掘機 v9.1.11 — 自動アップデートの検査失敗を修正

## 不具合と修正

v9.1.10には、コンソールのないGUIアップデーターから `--validate` を起動すると、検査用ログの標準エラー出力先がないことで異常終了する不具合がありました。通常起動や、出力をファイルへ転送するCIの検査では発生しませんでした。

実際の公開EXE（SHA-256 `cbbe82396409e10e1dc8df50171a133bcc7a151eac78f0a44ef35fca220e074d`）を取得し、アップデーターと同じ非リダイレクトのGUI起動条件で `--validate` が終了コード146になることを再現しています。同じEXEを出力リダイレクト付きで起動すると0、通常のUI smoke testも0でした。

v9.1.11では、検査用の補助ログを書けないだけで検査そのものを失敗させないようにしました。既存の検査項目、異常時の非0終了、署名・SHA-256検証、更新失敗時の旧版復元は削除していません。旧版アップデーター側の修正を先に要求せず、新しいEXE側で互換性を確保します。

また `--validate` が利用者の収納しきい値等の設定を読み込んで、固定条件の自己テストに影響する問題を防ぐため、検査用INIを一時領域へ分離しました。検査モードでは旧INIを移行・作成せず、既存の設定・診断ログ・STONE保存データを変更しません。通常起動時の設定読込・履歴移行は維持しています。

## 再発防止

`scripts/Test-UpdateStartup.ps1` を通常のビルドへ追加しました。コンソールも標準出力ハンドルも持たないGUI親プロセスから完成EXEを起動し、既定/カスタム設定の `--validate`、リダイレクトありの検査、非リダイレクトの `--smoke-test` を検証します。INI・旧INI・診断ログの不変性も確認します。

## 更新方法

自動操作をF9で停止してから、アプリの「アップデートを確認」を実行してください。旧版へ戻っている場合も、そのまま修正版を取得できます。

手動更新の場合は、現在のアプリを終了し、現在のフォルダーをバックアップしたうえで、配布ZIP内の `AI採掘機.exe` だけを同じフォルダーのEXEと置き換えてください。自分の `AI採掘機.ini` を配布テンプレートで上書きしないでください。Saved GamesやLocalAppDataのアプリデータを削除する必要はありません。

この版では石洗い・徒歩・収納・補充の処理や音声は変更していません。実FiveMでの新たな動作検証を行ったという意味ではありません。
