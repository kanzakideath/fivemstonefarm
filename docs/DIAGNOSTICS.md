# 診断ZIPの共有

## 不具合が起きたら

「設定」の「不具合の記録・診断ZIP」を開き、「今の不具合に目印を付ける」を押します。F9で作業を停止して「診断ZIPを保存」、保存先を選び、ZIPをこのチャットへ添付してください。発生時刻、石洗い/石掘り/砂金のどれか、期待した動きと実際の動きを一言添えると絞り込みやすくなります。ルート設定・アップデート画面にも入口があります。Web UIが使えないときはトレイメニューにも保存操作があります。

ログは自動的に外部へ送信されません。チャット側からPC内を直接読むこともできません。添付した分だけが調査対象になります。

## 保存とプライバシー

本体の共通保存先（通常はSaved Games/AI採掘機）のdiagnostics/events.jsonlと.1〜.4に、合計約10MiBの直近履歴を残します。1行の超過分を除いて各2MiBで更新します。起動ごとのsession、連番seq、UTC時刻、単調時刻、バージョン、FSM、作業/試行/タスク、入力と結果、停止理由を保持します。稼働中は5秒ごとの状態も残ります。診断機能自体はゲーム画面を撮影しません。既存の画像照合処理の基準画像をZIPへ入れることもしません。

ZIPは明示したログ・レポートの許可項目のみから生成します。INI全体・セーブ・音声・チャット・プロフィール・ルート画像は対象外です。パスやメール、接続識別子等は可能な範囲で除去しますが、未知の自由文の完全匿名化を保証するものではありません。共有前にZIP内のテキストを確認してください。

## 調査する順番

READ-ME.txt → manifest.json → last-events.txt → logs/events.jsonl（.4が最も古い）→ reportsを確認します。schema=1。USER_MARKは利用者の目印、FAULT/UNHANDLED_ERROR/WEB_ERRORは障害、WASH_REPORTは入力回数と画像計測、WASH_INPUTはヘルパー内のW押下/解除時刻です。WASH_INPUTにはWASH_REPORTのstartedUtcを基準にした相対時刻を含みます。TRACEは既存診断の安全化したメッセージです。ログは観測であり、キー受理・画像一致・操作可能・収納完了は別の確認です。

manifestのomissionsは取得できなかったファイル、skippedJournalLinesは途中書込み/不正JSONの行数です。これらがある場合にログ完備と判断しないでください。イベントは容量上限で古い順に消えるため、問題が起きたら早めに保存してください。保存したZIPは自動削除しません。

ディスク満杯/権限不足などでログを書けない場合は画面に失敗数を表示します。ログ失敗を理由に安全ガードを緩めたり、操作を再送したりしません。強制電源断などで未記録となることはあります。
