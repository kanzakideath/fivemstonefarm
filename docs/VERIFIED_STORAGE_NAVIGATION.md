# 徒歩収納・石洗い補充の修正候補

## 最初に確認すること

**従来の荷台ID登録だけでは、バン・トラックの現在座標は取得できません。**
徒歩往復を使うには、利用先サーバーの管理者がリポジトリ内の
`fivem-resource/ai_miner_companion/` を正規リソースとして導入し、
`config.server.lua` の所有権検証をサーバーのガレージ／DBへ接続する必要があります。
OneSyncと、対応する荷台インベントリ連携が必要です。
デスクトップEXEの更新だけで他者のサーバーにこの連携が導入されることはありません。
所有権検証の既定拒否を解除するだけの設定変更や、DLL注入、メモリ読取り、
アンチチート回避は行っていません。

詳細な導入方法は `../fivem-resource/ai_miner_companion/README.md` を参照してください。

## 登録と実行

1. 管理者による連携導入と車両所有権アダプター設定を完了します。
2. FiveMで停車した自分のバン・トラックの近くへ行きます。
3. アプリの車両画面から **徒歩往復する車両を登録** を選びます。
4. ゲームで車両を狙ってE、またはox_targetの登録項目を選びます。
5. アプリが候補の荷台まで移動し、荷台を開き、サーバー上の登録を確定します。
6. 自分で作業地点へ戻り、作業を開始します。開始時の位置と視点が帰還先になります。
7. 石掘り・砂金採りは容量しきい値で、石洗いは未洗浄石0または容量しきい値で、
   作業停止→徒歩到着→確定した作業成果の収納→必要なら石補充→徒歩帰還→作業再開確認へ進みます。

未洗浄石のアイテム名が未学習のときは、まず石を持って1回正常に洗ってください。
既存の学習処理は実際に消費したアイテムから名前を確定します。名前を推測しません。
補充数は荷台の在庫・所持重量・空きスロット・次の作業報酬用の余裕から計算されます。
必要な食料や道具を勝手に収納しないよう、今回の作業で増えた確認済み成果だけを搬出します。
荷台が満杯、補充石がない、所有権を確認できない、経路が塞がれている場合は理由を表示して停止します。

## 近接収納との違い

「近接収納だけ登録（徒歩移動なし）」は以前の荷台ID方式です。
少数のその場の荷台確認だけを行い、到達先の分からないランダムな徒歩探索は行いません。
既存の登録は勝手に徒歩連携登録へ変換しません。
徒歩連携で失敗した場合に、別車両を探すローカル探索へ自動フォールバックしません。

## 石洗い完了の音声

実際の最後の石が消費されたことを確認した際に、通知と「石洗いが終わったよ」の読み上げを行います。
通常は既存のWindows日本語女性音声優先のSAPI読み上げです。日本語女性音声がないPCでは、
別の利用可能音声や通知音になる場合があります。

専用録音を使用する場合は、EXEと同じフォルダーの
`audio/stone-washing-complete.wav` に10MiB以下の有効なWAVを置けます。
この修正に独自のニューラルAI女性音源は同梱していません。SAPIを新規AI音源と称しません。
音声再生は非同期で、読み上げ完了を待って補充ループを止めません。
同じ確定済み洗浄結果による通知の重複は既存の報酬確定・通知ガードで抑制します。

## 実装の境界

- `src/verified-storage-navigation.ahk`: 登録、徒歩移動の実行と到着応答照合、音声アダプター。
- `RunLocalVehicleStorageCycle`: 収納と補充の既存台帳／レシート処理を共有し、徒歩連携時の往路を切替。
- `CompleteVerifiedStorageReturn`: 徒歩連携時の帰還を `return-work` へ切替。
- `go-vehicle` / `return-work`: 許可されたゲーム内リソースがNavMesh徒歩タスクと実座標による到着確認を実行。
- 受領・受付だけの応答、登録ID違い、network ID 0、キャンセル、epoch不一致は到着とみなしません。
- F9停止と手動移動によるキャンセルを尊重します。無限追跡やテレポートはしません。
- 収納／補充は引き続き両インベントリの数量と操作レシートを照合します。不確定な要求を二重送信しません。
- `NAVIGATION_PROGRESS` ログで連携状態・目的地までの距離を確認できます。

## 検証の意味

`node scripts/Test-VerifiedNavigation.mjs` は入口の接続とUI表示の回帰テストです。
完成EXEの `--validate` は、本番と同じ徒歩オーケストレーションへ模擬アダプターを渡し、
到着応答・前後の照合・停止・キャンセルを検証します。
既存の収納・補充・ガチャ・保存・UIのビルド検証も維持します。

**これらは実FiveMでの歩行成功を証明する試験ではありません。**
配布前には導入先の管理者が、90/180度の視点変更、離れた停車車両、満量収納、
未洗浄石0からの補充、荷台満杯、補充在庫0、往路／帰路F9停止を実機で確認してください。
NavMeshのない地形、他プレイヤーが動かす車両、未ストリーム車両などの全条件での到達は保証しません。
