AI採掘機 v7.0.0 使い方
========================

重要
----
- 使用するFiveMサーバーのルールと管理者の許可を確認してください。
- v7の車両収納には、サーバー管理者が正規のFiveM resource
  `ai_miner_companion` を導入する必要があります。
- 利用者だけがローカルへ補助DLLやASIを入れて、他者管理サーバーで動かす方式ではありません。
- 初期状態のresourceは所有権検証が未接続のため、すべての車両登録を安全に拒否します。

対応環境
--------
- Windows 10 / 11（64 bit）
- FiveM
- 画面に日本語の対象ボタンが表示される環境
- 対象とox_inventoryのFiveM NUIへ接続できる環境
- 車両収納を使う場合: OneSyncとai_miner_companionを導入した許可済みサーバー

最初の準備
----------
利用者:
1. Releaseの「AI-Miner-v7.0.0.zip」を書き込み可能なフォルダーへ展開します。
2. 「AI採掘機.exe」と「AI採掘機.ini」を同じフォルダーへ置きます。
3. AI採掘機.exeを起動します。
4. 「設定」で開始キー、停止キー、バックグラウンド動作、残り重量を確認します。

サーバー管理者:
1. 「AI-Miner-Companion-v7.0.0.zip」をresources/[local]/へ展開します。
2. フォルダー名がai_miner_companionであることを確認します。
3. config.server.luaの所有権Validatorを車両DBまたはガレージexportへ接続します。
4. config.shared.luaのCargo設定を利用中のインベントリに合わせます。
5. server.cfgでOneSyncを有効にし、既定構成では次の順で起動します。
   ox_targetを使う場合もai_miner_companionより先に起動してください。

   ensure ox_inventory
   ensure ai_miner_companion

詳細はresource同梱のREADME.mdを参照してください。

基本操作
--------
1. ゲーム内で石または作業場所の前に立ちます。
2. AI採掘機で作業を選びます。
   - 鉱石を採掘する: 石の再出現を検知して採掘します。
   - 石を洗う: 約9秒周期で洗い、後退を小さくする前進補正を行います。
   - 砂金採りトレイ: 約6秒周期で繰り返し、未検出時は安全な範囲だけ位置補正します。
3. 「自動操作を開始」またはF8を押します。
4. 終了するときは「自動操作を停止」またはF9を押します。

バックグラウンド動作
--------------------
- 既定の「バックグラウンド動作」による対象NUI操作と、companion resourceによる車両操作は、1920x1080を含む解像度や画面上の絶対座標に依存しません。
- これらの既定経路は物理マウスや別アプリのキーボードフォーカスを奪いません。
- 対象NUIへ接続できない状態では開始しません。
- 砂金採りで対象を連続検出できない場合は、小さな境界付き補正だけを試します。最大範囲でも見つからないときは歩き続けず、手動調整待ちになります。

所持重量と収納条件
------------------
- 「設定」の「自動収納を始める残り重量 (g)」を使用します。初期値は2000gです。
- ox_inventoryのプレイヤー側weightとmaxWeightを優先し、次の式で判定します。

  残り重量 = 最大重量 - 現在重量

- 残り重量が設定値以下になると自動収納を開始します。
- 全スロット使用も補助条件ですが、全マスが埋まったかだけでは判断しません。
- 開始時点ですでに容量不足なら、新しい作業を行わず開始を取り消します。
- 容量情報を読めない間は新しい採集を止め、連続失敗時は安全停止します。
- 開始前の品をスロット・名前・メタデータ・数量で基準化し、開始後に増えた数量だけを収納します。

車両登録（座標・矢印キーなし）
--------------------------------
1. 登録する自分の車両の近くに立ちます。
2. 「車両」画面で表示名を必要に応じて入力します。
3. 「ゲーム内で車両を登録」を押します。
4. FiveMへ戻り、登録したい自分の車両へ近づきます。
5. 通常のox_targetで車両を選び「AI採掘機に登録」を押します。
   ox_targetを使わないサーバーでは、車両を画面中央へ合わせてHUDに表示された決定キーを押します。
6. サーバーが所有権を確認し、仮登録した車両の名前とナンバーがHUDに表示されます。
7. アプリが車両後部へ移動し、登録した荷台のtrunkを確認します。
8. 正しい荷台を確認できた場合だけ、車両登録IDとストレージIDを確定・保存します。途中で失敗した場合は以前の登録を維持します。

登録時にW/A/S/Dや矢印キーを記録する画面はありません。座標、カメラ位置、往路、復路も保存しません。旧版のRouteFormat 1/2/3は再生しないため、v7で一度登録し直してください。

動的な車両検出
--------------
- サーバー発行の登録IDは、所有者・ナンバー・モデルへ紐付きます。
- 車両の一時的なnetwork IDと座標は保存しません。
- 収納のたびにサーバーが現在の車両を再取得し、同じ所有者・ナンバー・モデルであることを照合します。
- クライアント側で車体の現在位置、向き、寸法から後部の接近地点を作り直します。
- 車両が少し動いた場合は接近地点を更新します。走り去る車両を追い続けたり、テレポートしたりはしません。
- 同じナンバーとモデルの候補が複数ある、車両が未ストリーム、設定距離を超える、所有権を確認できない場合は停止します。

自動収納中の動き
----------------
1. 作業開始時の徒歩位置を、一時的な作業アンカーとしてresource内に保存します。
2. 容量不足を検知すると新しい作業を止めます。
3. 登録IDから現在の車両をサーバー側で再解決し、network ID、所有権、車両一致、距離を検証します。
4. クライアント側で現在の車体寸法と向きから後部を計算し、FiveMのNavMeshで徒歩移動します。到着時にはサーバー側でも所有権、車両一致、距離を再検証します。
5. 登録時と同じtrunkだけを開き、今回増えた品だけを移します。
6. 作業アンカーへ徒歩で戻ります。
7. 元の作業ボタンを再検出できた場合だけ自動作業を再開します。

車両が消えた、動き続ける、徒歩経路が塞がれている、プレイヤーが死亡した、手動操作が入った、時間切れ、荷台不一致、収納失敗、または作業場所へ戻れない場合はFiveMタスクを解除して停止します。

サーバー再起動・切断
--------------------
- 開始時にFiveMのウィンドウ、プロセスID、対象・インベントリNUIセッション、companion resourceのepochを固定します。
- FiveM終了、プロセス置換、NUIセッション変更、resource再起動、サーバー再起動・再接続相当の変化では安全停止します。
- 読取り失敗中は作業と移動を凍結し、連続失敗時は停止します。
- 自動再ログインや切断後の自動復帰は行いません。
- 停止キーは必ずすぐ押せる別キーへ設定してください。

キーと設定
----------
- 「設定」で開始キー、停止キー、バックグラウンド動作、実行中に隠す、自動更新、各補正、残り重量を変更できます。
- 「設定を保存」でAI採掘機.iniへ保存します。
- 開始キーと停止キーは同じ値にできません。
- CompanionRegistrationId、StorageId、StorageType、RouteFormatは登録処理だけが保存します。手編集しないでください。

自動更新
--------
- 新しいデスクトップ版がある場合は「アップデート」画面とサイドバーに表示します。
- 更新先はkanzakideath/fivemstonefarmへ固定されています。
- ECDSA署名、SHA-256、サイズ、URL、置換後の自己検証が成功した場合だけ適用します。
- AI採掘機.iniは保持され、置換失敗時は以前の実行ファイルへ戻します。
- FiveM resourceはサーバー固有の所有権設定を含むため、アプリから自動上書きしません。更新前に稼働中のconfig.server.luaを別の安全な場所へバックアップしてください。
- 新しいCompanion ZIPは一時フォルダーへ展開し、新旧差分を確認して、新しいテンプレートへ所有権ValidatorとIdentityProviderの設定を手作業でマージします。既存のconfig.server.luaをZIPで直接上書きしないでください。

うまく動かないとき
------------------
- 車両画面が「サーバー連携が必要」と表示する場合、管理者にai_miner_companionの導入・起動を確認してください。
- 「所有権アダプター未設定」の場合、config.server.luaのValidatorがまだ初期状態です。
- 車両が見つからない場合、同じ車両が存在し、徒歩で到達できる安全距離内にあり、停止しているか確認します。
- 荷台が開かない場合、Cargo adapterと利用中のインベントリresourceを管理者に確認します。
- 旧方式と表示される場合、v7で車両を再登録します。矢印キーやルートの調整では直りません。
- サーバー再起動または再接続を検知した場合、ログインと作業位置を手動確認してから再開します。

制約
----
- 実サーバーの所有権DB、車両永続化、NavMesh、荷台実装はサーバーごとに異なります。
- 未ストリームの遠距離車両、別セッションの車両、航空機・船舶、徒歩到達できない場所は対象外です。
- 本ソフトウェアは無保証です。サーバーの規約を守り、利用者と管理者の責任で使用してください。
