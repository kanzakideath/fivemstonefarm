AI採掘機 v6.2.0 使い方
========================

対応環境
--------
- Windows 10 / 11（64 bit）
- FiveM
- 画面に日本語の対象ボタンが表示される環境
- 対象とインベントリのFiveM NUIへ接続できる環境

v6.2.0 の特徴
--------------
- 軽量なバックグラウンド操作で、物理マウスを動かさずに動作します。
- 対象ボタンとインベントリは構造的に扱うため、操作は画面解像度に依存しません。
- iOS/iPadOS標準アプリの情報階層を参考にしたネイティブWindows UIで、作業・車両・設定・更新を切り替えられます。
- 車両登録時だけ、ゲーム上に溶け込む暗色のクリック透過HUDを表示します。
- 作業モードは「鉱石を採掘する」「石を洗う」「砂金採りトレイ」の3種類です。
- 所持容量はサーバー側の重量と最大重量を優先して判定し、空きマスだけを満杯条件にしません。
- 車両登録ではW/A/S/Dの移動と矢印キーの視点を同時に記録し、裏画面でも再生します。
- 車両後部で登録済みの荷台だけを照合し、少しの駐車位置ずれは限定探索で補正します。
- FiveMのプロセスとNUIセッションを監視し、終了・再起動・再接続を検知した場合は安全停止します。

最初の準備
----------
1. Releaseの「AI-Miner-v6.2.0.zip」を、書き込み可能なフォルダーへ展開します。
2. 「AI採掘機.exe」と「AI採掘機.ini」は同じフォルダーに置きます。
3. AI採掘機.exe を起動します。Windowsの警告が出た場合は、配布元とSHA-256を確認してから実行してください。
4. 使用するFiveMサーバーのルールで、自動操作が許可されていることを確認してください。

基本操作
--------
1. ゲーム内で対象の石または作業場所の前に立ちます。
2. AI採掘機で作業を選びます。
   - 鉱石を採掘する: 石の出現を検知して採掘します。
   - 石を洗う: 約9秒周期で洗い、少しずつ後退する動きを前進補正します。
   - 砂金採りトレイ: 約6秒周期で砂金採りを繰り返し、位置ずれも安全な範囲で自動補正します。
3. 「自動操作を開始」を押すか F8 を押します。
4. 終了するときは「自動操作を停止」を押すか F9 を押します。

バックグラウンド動作
----------------------
- 「バックグラウンド動作」を有効にすると、物理マウスを動かさずFiveM内の対象ボタンを探して押します。
- ほかのアプリを操作中でも、そのマウスやキーボード入力を奪いません。
- 石洗い、砂金採り、車両収納はバックグラウンド動作を有効にして使用します。
- FiveM側のNUIデバッグ接続を利用できない状態では開始しません。アプリに表示される診断内容を確認してください。
- 砂金採りボタンを12秒間連続で検出できない場合は、前後・左右を小さく探る最大6段階の位置補正を行います。各段階の直後にボタンを再確認し、再検出すると補正状態は自動でリセットされます。
- 最大6段階の範囲でも見つからない場合は、それ以上移動せず手動調整を待ちます。キャラクターの向きや立ち位置が大きく変わった場合は、停止して位置を調整してから再開してください。

所持重量と自動収納の開始条件
----------------------------
- 「設定」の「自動収納を始める残り重量 (g)」で開始値を指定します。初期値は2000g、設定可能範囲は250～20000gです。
- アプリはox_inventoryが持つプレイヤー側のweightとmaxWeightを優先して読み、次の式で残り重量を求めます。

  残り重量 = 最大重量 - 現在重量

- 残り重量が設定値以下になったときに自動収納を開始します。インベントリの全スロットが使用中の場合も、補助の安全条件として収納を開始します。
- つまり「全マスにアイテムが入ったか」だけでは判断しません。重量制限に先に達した場合も検知します。
- 開始時点ですでに残り重量が設定値以下、または全スロット使用中なら、新たな作業を1回も実行せず開始を取り消します。先に所持品を整理してください。
- 実行中に容量情報を一時的に読めない場合は、その間の採掘・洗浄・砂金採りを止めて再確認します。3回連続で読めなければ安全停止します。
- サーバー側weightを取得できない場合のみ、各アイテムの重量合計を代替値として使います。

車両ストレージの登録
--------------------
車両収納は、残り重量が少なくなったときに、登録した車両後部の荷台へ今回増えた採集品を置いて作業位置に戻る機能です。最初に使うときは、実際にFiveMを起動した状態で車両とルートを登録してください。設定ファイルを手で書き換えて登録を作ることはできません。

登録前の条件:
- 「設定」でバックグラウンド動作をオンにします。
- 作業モードを選び、実際にその作業対象の前に立ちます。
- 車両後部で「ストレージを開く」「トランクを開く」「荷台を開く」のいずれかが表示され、開くとtrunk種類のインベントリになる車両を使います。
- 車両を作業場所の近くに駐車し、作業場所から車両後部までの通路を空けます。
- 登録時と自動収納時で開始位置と向きをできるだけ揃えます。

登録手順:
1. 「車両」画面で表示名を必要に応じて入力し、「車両とルートを登録」を押します。
2. FiveM上の登録HUDで 1/4 の作業場所確認が終わるまで待ちます。現在のモードの作業ボタンが見つからなければ、その位置では登録できません。
3. 2/4 の「開始待ち」で全キーを離してEnterを押します。「記録中」に変わったら、W/A/S/Dで車両後部まで歩きながら、矢印キーで視点を調整します。HUD上では押しているキーがアクセント色になります。物理マウスは動かす必要がありません。
4. 車両後部へ着き、荷台を開く対象が見える向きになったら、すべてのキーを離してEnterを押します。無操作時間による勝手な終了はありません。
5. 3/4 で荷台ボタンを自動確認します。見つからない場合は、登録を最初からやり直さず、W/A/S/Dと矢印キーで立ち位置・視点を微調整してEnterを押すと再確認します。最大8回まで調整できます。
6. アプリは対象を開き、右側インベントリの種類がtrunkであることを確認します。グローブボックス、地面、倉庫などは登録しません。候補が複数ある場合も誤登録を避けて停止します。
7. 4/4 では同じ操作で元の作業位置へ戻り、作業対象が見える視点まで記録してEnterを押します。作業ボタンが見つからない場合もその場で追加調整できます。
8. 元の作業ボタンを再検出すると、保存前の往復テストを開始します。記録した往路で同じ荷台IDと種類を開けること、復路で元の作業ボタンへ戻れることを自動確認し、すべて成功した場合だけ登録を保存します。テスト中は操作せず待ってください。
9. Escでいつでも登録を中止でき、中止時は移動・視点入力をすべて解放します。別画面へ移ると登録を破棄せず一時停止し、矢印キーとEnterも別アプリでは通常どおり使えます。キーを離してFiveMへ戻ると再開します。

登録経路を同じ速度で再現するため、登録中のShift・Ctrl・SpaceはFiveMへ送りません。走る・しゃがむ・ジャンプを使わず、W/A/S/Dと矢印キーだけで登録してください。

旧登録について:
- v6.1.0以前のRouteFormat 1/2は、v6.2.0では安全のため自動再生しません。
- 「車両」画面に「安全更新が必要」または「旧方式のルートは自動再生しません」と表示された場合は、v6.2.0で車両と往復ルートを登録し直してください。
- StorageIdやRouteFormatを手で変更して旧登録を有効化しないでください。

視点操作について:
- 登録した矢印キーは、再生時にFiveMの直接視点コマンド +look_up / +look_down / +look_left / +look_right へ変換します。
- 旧 *_only 方式で視点が動かなかった問題を避けるための変更です。停止・中断時はdirect、*_only、scaled_*_onlyを含むすべての視点入力を解放します。
- コマンド生成と解放はビルド時に検査していますが、実際のカメラ反応はFiveMクライアント、サーバー資源、入力設定の影響を受けます。オフラインテストだけでは実ゲーム内の視点移動を保証できません。
- 登録中に視点が動かない、または往復テストで荷台・作業ボタンを確認できない場合は、その登録を使用しないでください。

少し移動した車両の荷台探索
----------------------------
- 登録済みの往路を再生した位置で、最初に荷台ボタンを確認します。
- 見つからない場合は、その地点を探索原点として前後左右・斜めの短い8位置、同じ8位置と直接視点操作の組み合わせ、少し長い前後左右4位置の順で、最大20回の小範囲探索を行います。
- 各候補で荷台ボタンを構造的に検出し、開いたストレージのIDと種類trunkが登録値と完全一致するか確認します。
- 失敗した探索は必ず逆方向へ戻してから次を試すため、探索ごとの位置ずれを累積させません。
- 一致した候補からも、収納後に補正経路を逆再生して登録ルートの原点へ戻り、その後に登録済み復路を再生します。
- 探索幅は [VehicleStorage] SearchPulseMs で決まり、初期値180ms、入力範囲120～350msです。120～149msは内部で安全下限150msとして扱います。通常は変更しないでください。

この探索は、駐車位置が少しずれた場合だけを対象にした境界付きの相対探索です。車両の画像や3D位置を認識するものではなく、任意の場所へ移動した車両を追跡したり、障害物を避けて経路を作り直したりはできません。別の荷台、候補が複数、NUIエラー、探索経路を戻せない状態では何も収納せず安全停止します。

自動収納中の動き
------------------
- 容量不足を検知すると、新しい作業を止め、現在地が登録した作業位置であることを先に確認します。
- 登録済みの往路と視点操作をバックグラウンド再生し、必要なら上記の限定探索で荷台を探します。
- 荷台を開いた後、登録時のストレージIDと種類trunkの両方が完全一致するか確認します。一致しないストレージには何も移しません。
- 開始時のインベントリをスロット・名前・メタデータ・数量ごとに基準化し、開始後に数量が増えたアイテムだけを収納します。開始前から持っていた工具、食料、同名でも状態の異なる品は移さず保護します。
- 荷台のweight/maxWeightとスロットを確認し、入らない場合は移動を始めません。各スタックを移した後も、手元から減り荷台側で増えたことを確認します。
- 収納後にプレイヤーインベントリを再取得し、追加分が残っていないことを確認してからインベントリを閉じます。
- 補正経路と登録済み復路を再生し、元の作業ボタンを確認できた場合だけ自動で作業を再開します。

サーバー再起動・切断時の停止
----------------------------
- 開始前にFiveMのウィンドウ、プロセスID、対象NUI、インベントリNUIを確認します。いずれかを確認できない場合は開始しません。
- 開始後は標準3500ms間隔で、同じFiveMプロセスと同じNUIセッションであるか確認します。
- FiveMが終了した、ウィンドウが別プロセスへ置き換わった、または対象・インベントリNUIのセッション識別子が変わった場合は、サーバー再起動・再接続として自動停止します。
- ヘルス確認を一時的に取得できない場合は、その間の採掘・移動・収納を止めて再確認します。3回連続で失敗すると自動停止します。
- 登録時の往復テスト、通常の車両往復・荷台探索、砂金採りの位置補正では、移動ルートの開始時と累積約2.5秒ごとのステップ境界で、移動・視点入力をいったんすべて解放して開始時のNUI session epochと照合します。ステップ境界で確認するため、厳密な2.5秒周期ではありません。
- 車両へ到着した直後、荷台を開いて収納する直前、収納後に入力を解放して補正復帰・復路へ入る前にもsession epochを照合します。取得できない、または開始時と一致しない場合はルートを打ち切ります。車両処理は次の移動・収納へ進まず安全停止し、砂金補正は同じ未検出中の追加移動を行いません。
- 監視間隔は [Safety] ServerHealthIntervalMs で1500～10000msに設定できます。通常は既定値のまま使用してください。

この機能はサーバー固有の再起動通知を読むものではありません。FiveM/NUIが同じ状態のまま残る特殊な切断など、すべての障害を即時検知できる保証はありません。停止キーは必ず、すぐ押せるキーに設定してください。

制限と安全停止
--------------
- 車両収納はサーバーがtrunkとして公開する後部荷台だけに対応します。グローブボックスや独自UI、対象ラベルが異なるサーバーには対応しません。
- 任意の目的地への経路探索、車両の所有者判定、画面上の車種認識、大きく移動した車両の発見には対応しません。
- 通路に障害物や他プレイヤーがいる、開始時の立ち位置・視点が登録時と大きく違う場合は使用せず、ルートを登録し直してください。
- インベントリ情報を読めない状態が続く、開始前の持ち物だけで容量が不足している、車両に到達できない、荷台IDまたは種類が一致しない、候補が複数、収納できない、作業場所に戻れない、または復帰後の作業ボタンを確認できない場合は安全停止します。
- 停止後はFiveMの位置と車両を確認し、必要なら手動で戻してから再登録または再開してください。

キーと設定の変更
----------------
- 「設定」で開始キー、停止キー、バックグラウンド動作、実行中に画面を隠す、自動更新、位置補正、残り重量の開始値を変更できます。
- 「設定を保存」を押すと AI採掘機.ini へまとめて保存します。
- 開始と停止には別のキーを設定してください。必ず、すぐ押せる停止キーを用意してください。
- Route、StorageId、StorageType、RouteFormatは登録処理が検証して保存します。手で編集しないでください。

画面デザイン
------------
- メイン画面はWindowsネイティブGUIです。iOS/iPadOSの「設定」などを参考に、白いグループ一覧、システムフォント、単一の青いアクセント、暗色の状態カードで情報の優先順位を整理しています。
- 広い画面ではサイドバーと内容領域を使い、内容幅を必要以上に広げません。狭い画面では主要操作を優先して配置します。
- 車両登録HUDはゲーム画面を隠しすぎない暗色表示で、操作に必要な移動・視点・確定・中止だけを表示します。HUD自体はクリックを受け取らないため、ゲームのマウス操作を遮りません。
- Appleロゴ、偽の端末外枠、偽のステータスバーは表示しません。Windowsネイティブ部品の制約上、iOSそのものと完全に同一ではありません。

自動更新
--------
- 初期設定では起動後にGitHub Releasesの更新を確認します。
- 新しい版がある場合は「アップデート」画面とサイドバーに通知し、画面から適用できます。
- 更新先は kanzakideath/fivemstonefarm に固定され、任意のURLへ変更できません。
- 更新ファイルはSHA-256とECDSA P-256署名の両方を検証し、置換後の実行ファイルも自己検証します。
- AI採掘機.ini は更新時にも保持されます。適用に失敗した場合は以前の実行ファイルへ戻します。
- 署名が正しくない更新は適用されません。署名エラーが出た場合は実行せず、公式Releaseを確認してください。
- v5.1以前から初めて更新機能を使う場合は、v5.2.0を一度手動で導入してから署名付き更新を使用してください。

うまく動かないとき
------------------
- 対象ボタンの文字が「鉱石を採掘する」「石を洗う」「砂金採りトレイ」のいずれかになっているか確認します。
- FiveMを1つだけ起動し、対象の前に立ち直して再開します。
- 砂金採りが「手動調整待ち」になった場合は、対象ボタンが再び表示される位置へ手動で戻してください。アプリは範囲外へ歩き続けません。
- 車両画面に旧方式の表示がある場合は、RouteFormat 3として登録し直してください。
- 登録中に矢印キーで視点が動かない場合は登録を中止し、FiveMの入力設定とDevCon接続を確認してください。実FiveMの視点操作はオフラインテストでは再現できません。
- 自動収納で荷台が見つからない場合は、登録地点からのずれを小さくし、荷台ボタンが対応ラベルで表示されること、開いた種類がtrunkであること、通路に障害物がないことを確認して再登録します。
- 「サーバー再起動または再接続を検知」と表示された場合は、FiveMへのログインと作業位置を手動で確認してから再開してください。自動で再ログインや作業復帰はしません。
- 停止キーを押してから、AI採掘機を再起動します。
- サーバー側UIが変更された直後は、対応版が公開されるまで検知できない場合があります。
