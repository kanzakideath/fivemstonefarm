# AI採掘機 v9.1.17 — 高速石洗いの直接開始と重複確認の修正

作業開始ボタンの直下に「高速石洗いを開始」を追加しました。1回の操作で石洗いと高速モードを選び、既存の排他制御を通して開始します。自動収納・食事の設定は勝手に変更しません。通常の停止ボタン・F9はそのまま使えます。

クリック直前にも残っていたストレージ必須条件を修正しました。高速石洗いだけが専用のwork-only指定を送り、実際に使用できる「石を洗う」を1回選びます。通常モード・他の作業・収納先の検証は従来の条件を保ちます。洗浄対象が使えない場合に荷台や別の操作をクリックすることはありません。

v9.1.16の高速設定メッセージがWebViewホストの許可リストに入っていなかった問題も修正しました。見た目だけのプレビューではなく、本体の設定変更へ届くプロトコルをテストします。

高速洗浄中は定期容量監視の別個のインベントリ取得を行わず、クリック直前の報酬確認用スナップショットで容量と未洗浄石の残数を判定します。容量不足・石0などが実際に確認された場合だけ元の検証付き収納・補充へ移ります。期限切れの観測を流用せず、未確定の転送は従来どおり確認します。

インベントリの内部データ読み取り自体を廃止したわけではありません。石消費・成果取得・食品保護・重量上限を確認するための読み取りは残しています。この読み取りは荷台の探索や画面上でのストレージボタン待機とは別です。開始時に所持品データが未初期化の場合に限り、従来の一度の開閉で初期化し、その理由を表示・記録します。起動時の重複取得も削減しました。

収納後に廃止済みの徒歩関数へ入って失敗する経路を修正し、高速洗浄では荷台との同時表示を待たず再開処理へ戻ります。実際の再開成功は次の洗浄報酬を確認してから記録します。

診断: FAST_WASH_QUICK_START / FAST_WASH_READY / FAST_WASH_STORAGE_REQUIRED / FAST_WASH_BASELINE_RETRY / FAST_WASH_STARTUP_REUSE / INVENTORY_INITIALIZE_ONCE。

今回の更新は前進補正の復活・長距離徒歩・サーバー側作業時間の短縮ではありません。実FiveMの長時間運転・実測最短時間は未検証です。自動移動の無い版を維持しています。

更新は停止後にアプリのアップデート確認から。手動ではバックアップ後にEXEだけを置き換え、利用者のINIやセーブを上書きしないでください。
