# AI採掘機 v9.1.13 — 荷台前の微小後退を早めに計測・補正

今回の報告画像は WASH_SETTLING（待機段階）です。画像1枚だけでは、前進設定OFF・待機中・検出不足・ゲーム入力遅延のどれが実機の原因かは確定できません。

## 変更

確認済みの近接収納・石洗いに限り、毎回の実報酬確認後に `wash-maintain` を使用します。一般経路の0.65pxの許容範囲ではなく、0.20pxまでの微小なずれを扱います。このpxは256×144に縮小した画像の値で、ゲーム内の距離や座標ではありません。単にしきい値だけを変えず、整数位置の一致度からの3点近似を、画素間の移動を直接当てはめる方式で精密化しました。開始位置は固定したまま、洗うたびに後退した位置へ基準を更新しません。

短いW入力の後に画面を再確認します。効果のあった入力の直後に1回変化が小さかっただけで停止する条件を、連続して効果を確認できない場合の停止へ修正しました。最大8入力・合計360ms・1入力80ms以下・無反応2回・逆方向の悪化で停止する上限は維持します。誤方向・F9・手動操作・フォーカス喪失・キー解除失敗は続行しません。ずれがない場合に毎回強制前進して荷台へ押し付ける方式ではありません。

「両方のボタンが出る」は収納の操作範囲の確認であり、位置が戻った証明ではありません。前進補正を先に行い、限定した不確定結果だけ既存の操作範囲確認へ進みます。実収納・石補充では登録荷台ID、数量、metadata、両インベントリ、転送結果を引き続き確認します。

オーバーレイに前進補正ON/OFFを表示します。静止確認中はW未送信、送信後は回数と時間を表示し、待機と送信済みを混同しません。位置補正OFFを勝手にONへ変更しません。`WASH_RECOVERY_TICK` と `WASH_CORRECTION_PROFILE` をローカル診断ログへ記録し、`exe-routes/wash-position-last.json` に検査プロファイルと許容値も残します。

## 使用

F9で停止して更新します。「設定」の「作業位置と視点を自動復旧」をON、自動収納をONにして、荷台前の「この位置で近接収納を確認（歩かない）」を確認してください。確認済み近接設定では徒歩ルート不要です。未洗浄石を持ち、岩・岸など静止した景色を含む視点で、FiveMを前面にしてF8で開始します。オーバーレイの「前進補正ON」と、ルート設定の「荷台前・微小後退補正」を確認してください。

## 検証の区別

分数画素の移動検出、100回の累積微小後退、無変位、無反応、誤方向、キャンセルをコード試験します。Windows実画面の1px移動（縮小画像で0.25px）に対し本番ヘルパーが実際のW押下・解除を送る連続試験も追加しています。これらは合成画面の検証であり、実FiveMのカメラ追従、入力受付、長時間収納・補充や成功率の測定ではありません。最初の数回と最初の補充は見届けてください。

サーバー側導入、メモリ読み取り、アンチチート回避は追加していません。音声、転送の二重送信防止、v9.1.11の更新検査修正も維持しています。
