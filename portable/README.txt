釣りアシスト 0.1.0-preview — 独立した試用版
==============================================
採掘機の更新ではありません。FishingPilot.exeを直接起動します。
Windows 10/11 x64・.NET Framework 4.8用。サーバーへの追加導入はありません。
元の採掘機・INI・STONE・STONEVERSEには触れません。このアプリにはミニゲームを入れていません。
実FiveMでの成功率や連続運転を保証する完成製品ではありません。

使い方
------
1. ZIPをすべて展開し、旧採掘ツールを終了して FishingPilot.exe を起動します。
2. FiveMをウィンドウかボーダーレス表示にし、2番に釣り竿を置きます。
3. 食料・飲料キーを実際の配置に合わせます（既定1・3）。同じ品が両方回復するなら同じキーで構いません。
4. 初回は「観察テスト」ONのまま、3秒後開始→ゲームへ戻るか、FiveMでF8。
   手動で一度釣りをして、数字・円・重量・空腹・水分の表示を確認します。
5. F9で停止。「観察テスト」をOFFにし、手動の釣りが完了した状態から開始します。
6. 通常の停止はF9。前の接続処理が終わるまで、再開始に数秒〜十数秒かかる場合があります。
F8/F9が競合すると表示されたら旧採掘機を終了し、このツールを再起動してください。

自動操作
--------
2を1回押して投竿し、中央の円と数字を画面から読みます。
白い円弧の先端が緑の内側に入ったと観測できたときだけ、その数字を1回入力します。
数字変更と円の進行リセットを次の判定として扱い、同じ数字を要求される追加判定にも対応します。
円が一度消えただけでは再投入しません。対応UIの所持品増加または失敗通知を確認してから再投入します。
「取得確認」は所持品の正の増加を確認した回数です。魚の個数・種類を保証する表示ではありません。
釣り中に他の人から物を受け取るなどの別経路の所持品増加は、終了判定へ影響する可能性があります。

重量・食事
----------
重量上限または残りの余裕(既定500g)で、画面・通知音・Windows音声で通知し、次の投竿を保留します。
空きが戻れば再開します。満杯待ち中も、確認できる空腹・水分は補給対象です。
空腹・水分を別々に読み、50%以下の継続を確認して必要な側だけ補給します。
釣りのタイミング判定中には食事キーを混ぜません。補給後のゲージ上昇を確認して再開します。
ゲージを読めない場合は、勝手に食事したり満タン扱いにしたりせず確認待ちになります。
食料・飲料が切れた状態で餓死を防げるわけではありません。開始前に在庫を用意してください。
Windows音声は、そのPCの既定音声です。特定の人物の声ではありません。

ゲージの位置調整
----------------
自動検出が合わない場合、停止中にゲーム内の空腹アイコンの中心へマウスを合わせ Ctrl+Alt+F6。
水分アイコンの中心では Ctrl+Alt+F7。色付き外周の半径(px)も設定します。
初回の検出結果は、必ず目で見えるゲージと照合してください。
解像度やHUD配置を変えた場合は停止して位置を設定し直してください。

対応環境と限界
--------------
重量と終了確認は、既存ツールと同じ対応ox_inventory / ox_lib / ox_targetのローカルNUI接続に依存します。
初期所持品を読めないと表示されたら、ゲーム内で所持品を一度開いて閉じてください。
すべてのFiveMサーバーで同じNUIを使えるとは限りません。
FiveMは前面にしてください。別アプリへ切り替えると入力を保留します。
F9・FiveM終了・接続変更で入力を止めます。再起動後はF8で明示再開します。
判定不明、釣果未確認、餌・竿不足、補給未確認などで停止・待機することがあります。
「必ず無失敗」「再起動まで必ず稼働」「最速」を実測して保証したものではありません。
数字1/2/3の形は提供された記録由来です。他の数字はWindowsフォントの照合で実機未確認です。
ゲーム側の待ち時間・判定・報酬を書き換えません。メモリ操作やDLL注入はありません。
自動収納・前進・視点変更はありません。将来の収納用インターフェースだけ分離しています。

ログと検証
----------
設定とevents.jsonlは %LOCALAPPDATA%\FishingPilotPortable に保存します。ログは約4MiB×2世代です。
停止後に「診断ZIPを保存」で取り出せます。自動アップロードはありません。
通常動作で画像をディスク保存せず、全画面録画・チャット保存・入力文字列の記録は行いません。
共有前にZIPの中身を確認してください。
fixturesは記録から得た数字マスクと合成した円です。元の録画やゲーム場面は含みません。
Windows合成画面での入力試験と、実際のFiveMでの長時間運転は別です。
