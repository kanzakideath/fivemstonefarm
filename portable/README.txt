FishingPilot 0.5.0-preview — 釣りアシスト
=======================================
Windows 10/11 x64、.NET Framework 4.8、WebView2 Runtime用の独立した試用版です。
旧採掘機のmain・公開Release・署名付き更新先には変更していません。

更新と開始
----------
旧FishingPilotと採掘機を終了し、このZIPを新しいフォルダーへすべて展開してFishingPilot.exeを起動します。
EXEだけの差し替えは不可です。DLL・UI・SceneProbe.jsを含む一式を使用してください。
設定・荷台登録・ログは %LOCALAPPDATA%\FishingPilotPortable を引き継ぎます。削除不要です。
2番に釣り竿、設定した番号に食料・飲料を用意します。
「設定」で「観察テスト」OFF、「バックグラウンド動作」ON、「ゲーム上に状態を表示」ONを確認します。
FiveM上で F5開始 / F6停止。旧F8/F9は登録しません。画面の開始ボタンは3秒後に開始します。
初回の観察テストONではキーを送信しません。既存の設定を勝手に変更しません。

今回の不具合修正
----------------
バックグラウンド設定がONでも、ゲームが前面なら実際のクライアント画面とWindows入力を優先します。
以前はバックグラウンドONにより前面画像経路まで無効になっていました。
裏画面では対応NUIの描画値を優先し、DOMに円候補がなくてもゲームのNUI描画面から画像を調べます。
画像取得に円のDOM候補を必須にする循環した条件を撤去しました。
SVGの半径・中心が属性でなくCSSで定義されている場合も、描画時の値を読み取ります。
画像方式はクライアントの縦横比・サイズに合わせた領域を正規化し、複数中心・半径を調べます。
見つかった円は局所的に追跡し、重い探索を常に重ねません。
新しい背景画像入力経路では、ゲーム内で現在フォーカスされたNUIへブラウザーの数字キー押下・解除を送ります。
チャット・電話・所持品・入力欄などを対象にしません。入力先が確認できなければ理由を表示します。
対象外の別アプリへOSキーを送ったり、強制的にゲームを前面へ戻したりしません。

状態オーバーレイ
----------------
ゲームを前面にしたとき、クライアント領域の左上に状態を重ねます。
現在の処理・待機理由・認識方式・円と数字・所持重量・空腹/水分・所持品・取得累計を表示します。
クリックを通し、キーボードフォーカスを奪わない別ウィンドウです。ゲームへのDLL注入ではありません。
ゲームウィンドウの移動・サイズ変更に追従します。他アプリが前面の間はオーバーレイだけを隠します。
バックグラウンドの釣り処理は別です。状態はアプリの概要画面でも確認できます。
オーバーレイは一般的なウィンドウ/ボーダーレス向けです。排他的フルスクリーン上への表示は保証しません。
項目が多い場合、オーバーレイは一部の品目のみ表示します。全品目は概要画面に表示します。

現在の所持品と取得累計
----------------------
「現在の所持品」は実インベントリの置き換え式の一覧です。
手動収納・売却・破棄などで数が減れば減り、0個になった品は一覧から消えます。
釣り停止中も、アプリが開いていて対応UIの読み取りができれば所持品を更新します。
ホットバー1〜5の品と同名の品は保護品として一覧/累計から除外します。
アイテムの表示名を取得できれば表示名を使い、取得できなければ内部の品名を表示します。
「取得累計」は釣りの終了確認に伴う所持品の増加数を集計し、catch-history.jsonへ保存します。
手動収納しても累計は減りません。既に所持していた物や過去版の全履歴を推測で足しません。
別の人から同時に品を受け取ると釣果との区別ができない場合があります。
読み取りが途切れたときは前回値と「更新待ち」を表示し、空の在庫と偽って扱いません。
この一覧は非ホットバーの所持品であり、未知の品を魚と断定する分類器ではありません。

収納と補給
----------
既存の近接収納は維持しています。Altで荷台操作ができ、同じ位置で釣れる場所に停車してください。
停止中に荷台を手動で開き「荷台収納」で読み込み、収納したい魚だけを選択して登録します。
登録ID・品名・metadata・許可数量・両側の数量変化・転送結果を照合します。
未知の転送結果を無条件に再送せず、storage-pending.jsonを保持します。削除して回避しないでください。
移動・視点変更はしません。別の荷台/接続変更/転送不明で停止または確認待ちになることがあります。
食事と水分はそれぞれ50%以下で必要な側だけ補給し、回復を確認します。
ゲージ不明や在庫切れは満タンと扱いません。食料・飲料の事前準備が必要です。

裏画面の条件と限界
------------------
FiveMをウィンドウまたはボーダーレスのまま、最小化せずに他のアプリへ切り替えてください。
対応NUIと、ゲーム所有の登録ホットバー等の操作が使用できる必要があります。
最小化・ゲームの描画停止・ロック画面・スリープ・非対応UIでの継続は保証しません。
ゲーム側の判定・報酬・成功関数・アニメーションを変更しません。メモリ操作/アンチチート回避はありません。
取得できる情報や通常の入力方式に限界があるため、全画面/全サーバーで必ず無失敗とは言えません。
F6、接続変更、FiveM終了を尊重し、再接続後は明示的に開始します。

診断と検証
----------
停止後「診断ログ」→「診断ZIPを保存」で書き出します。自動アップロードしません。
バージョン・実行セッション・前面/裏画面・実際の検出元・円の有無・入力先未確認の理由を記録します。
一般の入力文字列・チャット・全画面録画は記録しません。共有前に中身を確認してください。
Windowsビルド・自己テスト・WebView2描画・合成SVG・ブラウザー入力・収納回帰試験と、実FiveMは別です。
配布のverification.jsonのlive_fivem_tested=falseは、実ゲームの長時間運転が未検証であることを示します。
テスト用オーバーレイ画像の品名/数量は「表示例」です。実際の釣果ではありません。
