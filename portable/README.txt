釣りアシスト FishingPilot 0.4.0-preview
=======================================
Windows 10/11 x64、.NET Framework 4.8、WebView2 Runtime用の独立した試用版です。
旧採掘機のmain・公開Release・更新先には変更しません。
実FiveMでの完全無失敗・すべてのUI対応・無期限稼働を保証する製品ではありません。

更新
----
旧FishingPilotと採掘機を終了し、ZIPを新しいフォルダーへすべて展開します。
FishingPilot.exeを起動してください。EXEだけでなくUI・DLL・SceneProbe.jsが必要です。
設定とログは %LOCALAPPDATA%\FishingPilotPortable を引き継ぎます。
設定画面の「観察テスト」OFFで自動入力、「バックグラウンド動作」ONで対応NUIへ入力します。
竿は2番、食料と飲料は設定したホットバー1〜5番へ。FiveM上でF8開始、F9停止。
開始ボタンは3秒後に開始します。3秒以内にゲームへ戻ってください。

近接荷台への自動収納
--------------------
1. 同じ立ち位置で釣りができ、Altで「ストレージを開く」が表示される場所にトラックを停めます。
2. 自動釣りを止め、登録したい荷台をゲーム内で手動で開きます。
3. アプリの「荷台収納」で「現在開いている荷台を読み込む」を押します。
4. 収納する魚だけを選んで「この荷台と選択した釣果を登録」を押します。
   初回の候補を表示するため、選びたい魚を手持ちのホットバー以外に置いてください。
5. ゲームで荷台を閉じ、同じ位置と向きからF8で開始します。登録時に自動収納はONになります。

初期設定では、開始後に増加を確認した、選択済みの品だけが収納対象です。
既に持っている魚も収納したい場合は、設定の「開始時の魚も収納」を明示的にONにします。
この設定でも、ホットバー1〜5、そのホットバーにある品と同名の品、武器、コンテナは対象外です。
竿・食料・飲料などを収納対象に選ばないでください。未選択の魚は自動で追加許可しません。

満杯または空き余裕（初期500g）
→ 進行中の釣りと結果の確認
→ 必要ならAlt相当のターゲット表示
→ 単一の近接荷台ボタンを選択
→ 開いた荷台ID・接続・プレイヤーIDを登録内容と照合
→ 一つのスタックずつ品名・metadata・許可数量で転送
→ 手持ちの減少、荷台の増加、元スロットの減少、転送結果を照合
→ 荷台を閉じたことと最新の空き容量を確認
→ 次の釣りを開始し、進捗または数字判定で開始を観測
という流れです。移動や視点変更はしません。

同じ位置で両操作が可能なことは利用者が実際に確認してください。
ボタン表示だけでは荷台ID・収納成功・釣り成功の証明にはしません。
荷台満杯・対象の魚なし・近接ボタンが見えない場合は間隔を置いて確認します。
別の荷台、接続変更、曖昧な候補、転送結果不明の場合は誤転送せず待機または停止します。
ゲーム再接続後は荷台を再登録してください。

転送途中の終了や応答遅延に備え、転送前にstorage-pending.jsonを原子的に記録します。
未確定の転送を自動で再送しません。再起動時は同じ荷台を開いて両側の変化を再確認します。
このファイルを削除して確認を飛ばす使い方はしないでください。
手持ち・荷台を同時に他の人が操作した場合は、正しい照合ができず停止することがあります。
釣り中に同じ魚などを別の人から受け取ると、釣果との厳密な区別ができない場合があります。

認識
----
対応するSVG円は描画された中心・半径・回転・円弧・数字を読み、同じ処理内で判定と通常キー入力を行います。
複数候補、色の役割の矛盾、古い接続、インベントリ表示中には入力しません。
画像方式の「高精度の画像認識」は複数中心・複数半径の広域探索、数字形状、円弧、連続観測を使います。
見失ったときだけ重い探索を使い、追跡中は局所的に処理します。
認識を重くするほど入力が遅くなることもあるため、処理時間と方式を表示・記録します。
数字と円を確認できない画面を推測だけで押したり、緑の判定を広げたりしません。
すべての解像度・配置・テーマ・サーバーUIに対応するという保証はありません。

裏画面と補給
------------
FiveMをウィンドウまたはボーダーレスのまま、最小化せずに別アプリへ切り替えます。
対応NUIとFiveM所有の登録ホットバー／ターゲット入力に依存します。
非対応UI・最小化・ロック・スリープ・描画停止・接続変更での継続は保証しません。
別アプリへWindowsキーを送る代替処理はありません。
食事と水分は別々に監視し、50%以下で必要な側を補給、回復を確認します。
読み取り不明は満タン扱いにせず待ちます。食料や飲料がなければ餓死は防げません。

診断
----
停止後「診断ログ」→「診断ZIPを保存」で書き出します。自動送信はありません。
認識方式、入力、待機理由、転送意図、転送結果、両側照合、釣り再開の観測を記録します。
荷台登録と転送記録には荷台ID、品名、metadataなどゲーム上の情報が含まれます。
共有前に中身を確認してください。元の録画・チャット・一般の入力文字列は保存しません。

検証と配布
----------
Windows自己テスト・実WebView2描画・合成SVG/画像・実転送式に対する模擬応答の試験を実行します。
検証結果JSONのlive_fivem_tested=falseは、実FiveMでの連続運転を試せていないことを示します。
実行ビルドと検証結果を一緒に配布します。署名付きの採掘機自動更新には登録していません。
