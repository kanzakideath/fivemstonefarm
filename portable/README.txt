釣りアシスト 0.2.0-preview
=============================
これは FishingPilot の独立した更新版です。AI採掘機の更新先・mainには変更を加えません。
Windows 10/11 x64 + .NET Framework 4.8。ZIPをすべて展開して FishingPilot.exe を起動します。
旧 FishingPilot/採掘機を終了してください。既存の設定とログは同じLocalAppDataフォルダーを使います。

使い方
1. 2番に釣り竿、設定した1〜5番のホットバーに食料・飲料を用意します。
2. 初回はFiveM上でF8。自動操作は「観察テスト」をOFFにします。
3. 「バックグラウンド動作」をONで、対応NUIの円・数字と登録ホットバーから操作します。
   別アプリが前面でもWindowsの数字キーをそのアプリへ送信しません。
4. F9で停止できます。設定は停止して変更してください。

修正内容
・釣果を確認してすぐに2を送って終わる方式を変更しました。
  最後の判定入力後の回復、結果の後の猶予、進捗表示の終了、連続した円の不在を確認します。
  投竿送信と受付の観測を別に記録します。追加判定中は再投入しません。
・投竿の受付が一度も観測できず、円・進捗も出ない場合、65秒以上待って限定再試行します。
  最大2回です。受付を確認した釣りや結果不明の釣りに、短時間で2を連打しません。
  ゲーム固有の非常に長い待ち時間と入力無反応を、UIだけで必ず区別できるわけではありません。
・結果確認12秒の打ち切りをなくし、確認待ちのまま追加判定・結果を監視します。
・既に数字判定中から開始した場合、観測できた判定を引き継ぎ、余計な2を送りません。
・円がSVGの場合は描画中の中心、半径、回転、円弧長、数字をNUIから取得します。
  解像度ごとの固定座標ではありません。画像方式も正規化と複数中心候補を追加しています。
・バックグラウンドの画像はNUIの描画面から取得します。他アプリの画面は撮影しません。
・水分・空腹の判定領域を高さに応じて正規化し、明示的なNUIゲージ値があれば優先します。
  50%以下で補給する条件、重量満杯通知、F9、接続変更時停止は維持しています。

重要な制約
・全サーバー・全UIに対応したものではありません。既存と同じox_inventory/ox_lib/ox_targetの
  ローカルNUI接続を使用します。取得不能時にゲームメモリや成功コールバックへ切り替えません。
・裏画面ではゲームの登録hotkey1〜5を使い、判定数字は検出したNUIフレームに通常の
  keydown/keyupイベントを送ります。対象NUIがこのイベントを受け付けない場合、進みません。
  その際、別アプリにOSキーを送るフォールバックはありません。
・FiveMを最小化せず、ゲームが描画・処理を続ける状態で他のアプリを前面にしてください。
  最小化・ロック画面・スリープ・ゲーム側の停止や描画抑制下での継続は保証しません。
・タイミング判定の成功率100%、あらゆる解像度での成功、実FiveMの最短サイクルは未検証です。
・画面の通知が対応形式でない場合、所持品の増加と円の終了を組み合わせて結果を確認します。
  他の人から同時にアイテムを受け取ると釣果と区別できないことがあるため、避けてください。
・ゲージ不明は満タン扱いにせず待機します。食料・飲料不足で餓死を防げる保証はありません。
  自動補給ONのまま待つ場合は、実際のHUDと認識表示を確認してください。
・自動収納はありません。満杯では通知して新しい投竿を保留します。

ログ
%LOCALAPPDATA%\FishingPilotPortable
「診断ZIPを保存」で書き出します。2秒ごとの状態、待機理由、NUI/画像の方式、読み取り時間、
投竿送信/受付/再試行、数字入力、結果、バージョン、実行セッションを記録します。
自動アップロード・全画面録画・文字入力全体の保存はしません。

検証は添付のvalidationに記録します。合成UI・Windows試験と実FiveM試験は区別しています。
