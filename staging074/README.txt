FishingPilot 0.7.4 preview — ビルド済み Windows x64

【0.7.4の目的】
0.7.3をそのまま基準にし、価格表へ登録済みの品だけを通常画面・オーバーレイ・
収納候補へ表示します。未登録品の価格は推測しません。
空腹・水分のどちらが低下しても共通補給キー（初期値1番）を使います。0.7.3の
水分3番キーは廃止し、既存の食料・水分設定は共通補給キーへ移行します。
旧設定・釣果履歴・荷台登録・Admin端末登録は削除しません。

バックグラウンドとフルスクリーン経路は、別アプリへ数字キーを送らず、対象FiveM/NUIを
確認した入力だけを使います。画面キャプチャを取得できない場合は、同じFiveMプロセスの
ゲームNUIを別スレッドで補助監視し、フルスクリーン切替後の窓も再確認します。所持品同期が
止まった結果の後は釣果を加算せず、独立した所持品確認と検証済みスロット経路を待ってから
再投入します。同じFiveMプロセス内でゲームNUIが再生成された場合は、旧入力を
解除し、新しい所持品と停止中の釣り画面を確認して再開します。この切替中の
釣果は加算せず、荷台の接続識別も変わった場合は自動収納だけをOFFにします。
同じ円の追加判定は別回として追跡し、更新されない古い描画へは入力しません。
キー解除は同じ処理内で実行します。ウィンドウ、ボーダーレス、非アクティブ、他ウィンドウ
被覆を区別して診断します。exclusive fullscreenを含む実FiveM確認の有無は
FishingPilot-0.7.4-package-verification.jsonを参照してください。CIのfixture成功だけを
「全環境で確実」の根拠には
しません。最小化・画面ロック・スリープ、またはゲーム側がNUI描画や入力受付を停止する状態
までは継続を保証しません。

【起動】
旧FishingPilotを終了し、初回または更新管理自体を更新する場合はfull ZIPを新しいフォルダーへ
すべて展開します。一番上のFishingPilot.exeを起動してください。.NET Framework 4.8と
WebView2 Runtimeが必要です。F5開始 / F6停止は変更しません。

【自動更新】
0.7.1以降の互換Managerで自動更新がONなら、起動時と30分ごとにFishingPilot専用Releaseを
確認します。運転中には差し替えず、終了後または次回起動前に適用します。ZIPと同じReleaseの
SHA-256を照合し、安全な相対パスだけを展開します。これは公開鍵署名やAuthenticode署名では
ありません。更新管理EXE自体を変更した版は、full ZIPを一度導入する必要があります。

【0.7.3へ戻す】
full ZIPには公開済み0.7.3 appを固定SHA-256で同梱しています。本体を終了して更新管理から
0.7.3を選び、「選んだ旧版に戻す」を実行します。rollback後は自動更新がOFFになります。
設定を戻すかは別に選択でき、釣果履歴・収納台帳・Admin登録は巻き戻しません。

【公開前検証】
配布物はnative build/startup、NUI/JS、入力lease、同一数字追加判定、inventory、storage、
Admin、共有、updater、rollback、UI幅の各試験を通過した後だけdraft Releaseへuploadします。
branchへの通常pushはbuild/testだけで公開しません。公開はworkflow_dispatchでpublishを明示し、
既存の`release` environmentを使います。draft上の全assetを再downloadしてローカルpackageと
一致した後に公開します。公開feedを
0.7.3/0.7.4両Managerで確認できない場合は、Releaseを直ちにdraftへ戻します。

異常時はF6で停止し、診断ZIPを保存してください。パスワードや端末登録情報は共有しないで
ください。実FiveM、実際の別宅回線、長時間負荷の確認結果をpackage verificationより強く
言い換えないでください。
